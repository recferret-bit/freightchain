Возрождение культа Desert Bus в Web3

Проект берет культовую механику игры 1995 года Desert Bus (где необходимо непрерывно в течение 8 часов вести автобус по прямой трассе без автопилота, с постоянным микро-уводом вправо) и упаковывает её в Telegram Mini App со ставками на выносливость и прогрессивным джекпотом.

04 КЛИЕНТСКИЙ АНТИЧИТ & ОБФУСКАЦИЯ

Защита открытого браузерного окружения

Браузер заведомо скомпрометирован. Чтобы сделать создание автопилота экономически невыгодным, применяется комплекс многослойной защиты:

1. Rust / WASM + OLLVM

Вся логика инпутов, физика и сериализация упаковываются в WebAssembly с флагами Control Flow Flattening. Символьные таблицы удалены, переменные замаскированы. Декомпилятор выдает нечитаемый граф из сотен условных переходов.

2. Криптографический храповик пакетов (Input Ratchet)

Каждый кадр ввода формирует непрерывную цепочку хешей HMAC-SHA256. Нельзя внедрить виртуальный кадр без знания состояния предыдущего кадра и секретного серверного nonce.

S(n) = HMAC_SHA256(S(n-1), Input(n) || DeltaTime(n) || ServerNonce)

3. Физическая аналоговая энтропия (Touch & Motion)

Сбор данных с мобильного сенсора: эллипс соприкосновения пальца (radiusX/Y, rotationAngle), сила нажатия (force) и показания гироскопа/акселерометра (DeviceMotionEvent). Искусственные скрипты выдают нулевой джиттер или статичные эллипсы, что приводит к мгновенной дисквалификации.

4. Proof-of-Render (WebGL Framebuffer Check)

WASM периодически запрашивает хеш определенного участка внеэкранного буфера рендеринга (gl.readPixels). Бот обязан честно задействовать видеочип и рендерить графику, что лишает ботоводов возможности дешево запускать 1000 headless-инстансов в облаке.

05 БЭКЕНД ДЕТЕРМИНИРОВАННОЙ ВАЛИДАЦИИ

Архитектура Headless-симуляции

Сервер не верит клиенту. По завершении 8-часового заезда бэкенд прогоняет лог нажатий через движок симуляции на скорости свыше 50 000 тиков/сек.

Компактный бинарный кадр инпута (7 байт при 60 Hz)
#[repr(C, packed)] struct TickFrame { steering: i16, // Угол поворота руля [-32768..32767] throttle: u8, // Педаль газа [0..255] brake: u8, // Торможение [0..255] flags: u8, // Битовая маска тачей и ручника mac_tail: [u8; 3], // 24-битный срез контрольной суммы Ratchet }
Объем за 8 часов (1.728M тиков): ~12.1 МБ сырых При zstd сжатии: ~1.8 МБ

Фиксированная точка (Q32.32)

Полный запрет на использование float/double. Никаких расхождений IEEE-754 между ARM (iPhone/Android) и x86_64 (серверный Linux). Все векторы и тригонометрия вычисляются целочисленно через LUT/CORDIC.

Хеши контрольных точек (XXH3)

Каждые 300 тиков (5 секунд) генерируется хеш состояния (координаты, скорость, угол). При несовпадении контрольной точки валидация прекращается за миллисекунды (Early-Reject), экономя ресурсы воркеров.

06 РЕНДЕРИНГ И ЖИЗНЬ АККУМУЛЯТОРА

Гибридный стек (WASM Core + JS WebGL)

Рендеринг всей игры внутри WASM раздувает бандл до 10-15 МБ. Рекомендуемое решение — гибрид: WASM производит расчет физики и держит буфер трансформаций, а Three.js / Pixi.js выполняет отрисовку через Zero-Copy доступ к памяти WASM.

Регламент энергосбережения для 8-часовой сессии:
  • Screen Wake Lock API: Предотвращает гашение экрана устройства во время монотонного движения по пустыне.
  • DPR Clamping (1.5x max): Принудительное ограничение разрешения холста на дисплеях Retina/AMOLED для предотвращения перегрева GPU смартфона через 40 минут.
  • FPS-Lock на 60 кадров/сек: Запрет на разгон до 120 Гц ProMotion для экономии заряда батареи.
  • Запланированные пит-стопы: 3 обязательные паузы по 5 минут на «заправках» для отдыха глаз игрока, охлаждения устройства и реконнекта сокета.
07 СТРАТЕГИЯ ЗАПУСКА (GTM)

Telegram + TON: Победа без бюджета на маркетинг

📢 Кладбищенский стрим-канал

Бот в реальном времени публикует в публичный канал драмы: «Игрок @alex_tma уснул и разбился на 7-м часу 12-й минуте. Пул $2,840 перенесен на следующий раунд». Это генерирует мощный органический FOMO.

🌪️ Зрительский саботаж

Зрители стрима в Telegram покупают за Stars или микро-TON препятствия водителю (густой туман на 10 секунд, выбоина на дороге). 70% средств с этих микротранзакций уходят прямиком в джекпот, привлекая новых кандидатов.

⚠️ Защита от блокировок магазинов приложений (Apple App Store Risk)

Поскольку Apple жестко фильтрует азартные механики в Telegram Mini Apps на iOS:

  • Все депозиты проводятся строго через некастодиальный TonConnect (без встроенных IAP).
  • Развертывается резервное PWA-зеркало в Web: при блокировке Mini App игрок может продолжить сессию через прямую ссылку в браузере Safari/Chrome.
