# Achievements + their soulbound NFTs – detail

Agent reference (see AGENTS.md "Maps stay current"). Read it before changing the catalogue, the mint job or the badge art.

## In short

- **Catalogue** `server/src/domain/achievements/achievements.ts` (import-free, so `design/achievements/generate.mjs` reads it): 9 families × 3-4 tiers (Bronze / Silver / Gold / Platinum) = 34 badges + the legacy `top-20` (never earned, never minted). The ninth is `honk` (HONK): `honk-haul`, `honk-haul-2`, `honk-haul-3`. A tier is earned when `measure(facts) >= target`; `progressOf` feeds the lobby's locked cards.
- **Ids are FROZEN** once a wallet could have earned them (unlock rows and, later, minted leaves reference them). Tier 1 keeps the id the family had before the ladders; a new tier = a new id. Never retune a target of a shipped tier – add a tier.
- **Shifts are PAID only**: the Shifts family reads `paidShifts` (completed rides of any paid tier); a free ride never counts, however it ends. The other families count free rides too (Solo and Licence are free-only by definition). Changing this for tier 1 re-judges the frozen id `shift-complete` at mint time: an old unlock earned by a free ride is `skipped` (`no-longer-earned`), never minted.
- **Facts** (`Facts`, `RideQueryPort.summary`): counts, not flags – `started`, `completed`, `totalMetres`, `nightShifts`, `cleanRuns`, `siberiaShifts`, `freeUnassisted`, `completedFreeLevels`, `honkMints` (verified mint rows with amount > 0), `honkFinishes` (those with the 100% band). Only what the server derives; a rejected recording earns nothing while the verdict is enforced (`badgeRejected`). A harder condition needs a new fact in BOTH `ride-query.prisma.repository.ts` and the in-memory twin.
- **Unlocks** (`achievement.AchievementUnlock`) are append-only, written at `/end` and caught up on a profile read. **Mints** are a separate outbox (`achievement.AchievementMint`: planned → sent → minted | failed | skipped); an unlock is never edited.
- **The NFT**: Bubblegum **v2** compressed NFT (`mintV2`) in an **MPL-Core collection** with the `BubblegumV2` + `PermanentFreezeDelegate` (frozen, authority None = nobody can thaw) plugins = **soulbound**; leaf owner = the player's wallet, a private tree, the achievement key signs and pays. Metadata JSON + PNG on **Arweave (Irys)**; the URI is baked into every leaf – re-uploading gives NEW mints a new URI only.
- **The job** `MintAchievementsHandler` (`AchievementMintScheduler`, CLI `node dist/cli/index.js achievement:mint [--retry]`): queue unlocks older than `ACHIEVEMENT_MINT_DELAY_MS` whose metadata is uploaded (demo wallets `skipped`) → resolve `sent` rows by signature (landed → asset id from the transaction; failed / expired → planned again, `failed` after `MAX_MINT_ATTEMPTS`) → mint `planned` rows after re-checking the badge against facts that ALWAYS skip rejected rides (a token cannot be taken back). The signature is stored (`claimSent`) BEFORE the broadcast, like `PoolPayout`.
- **Off by default**: the job needs `ACHIEVEMENT_MINT_SECRET` + `ACHIEVEMENT_TREE` + `ACHIEVEMENT_COLLECTION` and a non-empty `nft-metadata-uris.ts`. A separate key – never the crank or payout key; it can mint and nothing else.
- **Analytics**: `achievement_unlocked` (+ `family`, `tier`, `tier_name`), `achievement_minted`, `achievement_mint_failed` (server), `achievement_nft_clicked` (browser). Keep `docs/analytics/index.html` in step.

## Detail

- **Links + sharing** (`client/site/lobby-achievements.js`): a minted badge links the Solana Explorer, Solscan and Orb (all read cNFTs through DAS) and the mint transaction (the receipt that never needs an indexer), plus POST ON X; the profile footer links the collection and the Merkle tree (`ProfileDto.badgeChain`, from `ACHIEVEMENT_COLLECTION` / `ACHIEVEMENT_TREE`) and says Phantom, Solflare and Backpack list v2 cNFTs under collectibles (marketplaces – Tensor, Magic Eden – do not yet; a soulbound badge needs none). Cluster = `CLUSTER` in `pools.js` – change it with the program's.
- **Tree guard**: each pass reads the tree's `numMinted` / capacity (`treeUsage`); from 90 % it logs an error, a full tree sends nothing (rows stay planned) until `setup-tree.mjs` + a new `ACHIEVEMENT_TREE`. Unreadable = unknown, no guard (verify the read on devnet).
- **Metadata** (Metaplex standard): `seller_fee_basis_points` 0, `collection`, attributes Family / Tier / Tier Number / Condition / Requirement (number) / Soulbound / Game, `properties.files` PNG.
- **Profile DTO** (`AchievementDto`): `family`, `tier`, `tierName`, `progress {value, target}`, `nft {status, assetId, signature} | null`. The lobby (`client/site/lobby-achievements.js`) draws one ladder per family of flip cards. Front: badge (its art carries the three level stars), name, the date earned, or for a locked one its progress bar (the family's next level also shows its condition). Back (hover, keyboard focus or tap; Solana-coloured sweep, plain crossfade under `prefers-reduced-motion`): the condition and – once minted – cNFT / Solscan / Orb / mint tx / Post on X (`CLUSTER` of `pools.js`).
- **Art** `design/achievements/generate.mjs` (no dependencies; `node design/achievements/generate.mjs`): per badge an earned and a locked SVG (three stars under the name banner, no tier text; the locked one is steel with a padlock) → `client/site/img/achievements/` (the lobby), an earned PNG → `design/achievements/out/png/` and the metadata JSON → `design/achievements/out/metadata/` (what Irys gets). `preview.html` is the contact sheet. Rendered with headless Chrome.
- **Upload** `server/scripts/achievements/upload-irys.mjs --keypair K --cluster devnet|mainnet` (dry run unless `--yes`, cached by content hash) writes `src/domain/achievements/nft-metadata-uris.ts` (`NFT_METADATA_URIS`, `NFT_COLLECTION_URI`). Commit that file; it is what makes a badge mintable.
- **Tree + collection** `server/scripts/achievements/setup-tree.mjs --keypair K [--cluster devnet] [--depth 16 --buffer 64 --canopy 10] [--thaw-authority] --yes` (dry run by default) creates both and prints the three env lines. Depth 16 = 65,536 badges, ~0.7 SOL rent on mainnet (depth 14: 16,384 badges, ~0.34 SOL). Tree shape and canopy are immutable. Mainnet needs `--rpc` and `--i-know-mainnet` – **mainnet waits for the devnet tests** (see AGENTS.md "Escrow" and `docs/escrow-open-items.md`).
- **Smoke test** `server/scripts/achievements/smoke-mint.mjs --keypair K --tree T --collection C --yes`: mints one badge to a throwaway wallet, waits for finalization, reads the asset id, then tries to TRANSFER it as the owner – it must be refused (needs an RPC with the DAS API for the last two steps).
- **Env** (four places, AGENTS.md): `ACHIEVEMENT_MINT_SECRET`, `ACHIEVEMENT_TREE`, `ACHIEVEMENT_COLLECTION`, `ACHIEVEMENT_MINT_INTERVAL_MS` (120000; 0 = CLI only), `ACHIEVEMENT_MINT_DELAY_MS` (3600000), `ACHIEVEMENT_MINT_BATCH` (10).
- **Failure modes**: a simulation that would fail leaves the row `planned` with the error (nothing claimed); a signed transaction that never lands is resolved from its signature (`expired` → a new one is safe: the blockhash is gone); `failed` rows wait for `achievement:mint --retry`. The asset id is read from the finalized transaction – until then the row stays `sent`.
- **Not done**: a `podium` family (round / pool winners – `top-20` is only a placeholder); a DAS-based reconciler that cross-checks `minted` rows against the tree; mainnet tree + collection; wallets (Phantom / Solflare / Backpack) show v2 cNFTs but marketplaces do not yet – which suits a soulbound badge.
- **Tests**: `test/unit/domain/achievements.spec.ts` (ladders, exact targets, frozen legacy ids), `…/mint-achievements.handler.spec.ts` (delay, demo, crash-after-sign, expiry, attempts, concurrency, batch), the scheduler + adapter specs, `achievement-mint.prisma.repository.integration.spec.ts` (claims under real concurrency), the profile scenario in `test/scenarios/lobby.scenarios.ts`.
