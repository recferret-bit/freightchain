# Live board + live streams – detail

Agent reference, moved verbatim out of `AGENTS.md` (which keeps only the map and the hard rules and is loaded into every agent session). Read the file for a topic before changing it; keep it current like AGENTS.md ("Maps stay current").

## In short

- **Live board** (detail `docs/agents/live.md`): `GET /api/live` = rides with a heartbeat within `HB_TIMEOUT_MS` + soft `online` counts (in memory, ≤ 3 ids per IP; pages send `visitor` + `page`), `GET /api/replays` = the public history (cursor). A ride silent for `HB_TIMEOUT_MS` (150 s) is ENDED by the stale-ride sweeper (*failed · heartbeat lost*, under the owner's player lock) – never leave a ride `running` because its tab vanished. Closing a page is seen at once: landing / lobby / watch poll once more with `leave=1` on `pagehide` (`site/presence.js leaveOnClose`); the game tab `sendBeacon`s `/end` (text/plain, parsed only there by `beaconBodyMiddleware`) and ENDS its ride; a back/forward-cache restore of that tab reloads. After touching it: skill `live-board-test`; `server/scripts/sim-rides.mjs` fakes drivers / visitors / watchers.
- **Live streams** (spectators, `play.html?watch=<rideId>`; explainer `docs/replay-and-donations/index.html` – keep its numbers in step with `live-rules.ts` / `watch.js`; detail `docs/agents/live.md`): everything is a poll, the verified-play batches ARE the stream (~25 s behind). A replay plays the recording into `st` (`st.watch` = no sim, no input, traffic SIM off – the recorded 2 Hz traffic, outside the hashed batch text, dropped never refused, is drawn) on the road rebuilt from seed + route with the SERVER's holes. The sample row is shared with the verdict – only APPEND columns (12 clock hour, 13 `FLAGS`, 14 input bits `js/input-bits.js` – frozen, `map` skips bit 25 = MOUSE, 15 fork road). Feature flags `LIVE_CHAT` all|free|off · `LIVE_DONATIONS` on|off · `LIVE_FREE_DONATIONS` on|off · `LIVE_EFFECTS` all|free|off (code all/on/on/all, prod compose all/on/off/free), enforced by `LiveAccessService`, the pages read `features`. Paid donations: devnet SOL from the spectator to the DRIVER, confirm claims the order once (signature unique) → a NEW feed event; money that moved is never refused (delivered as a tip with the reason); a paid hole's place is the driver game's stamp. Effects keep a sliding 20 s gap under a per-ride advisory lock; mutes and stamps are the owner's, under the player row lock. The replay draws the driver's cosmetics (`ride.loadout`). After touching `watch.js`, `ui/watch-panel.js`, `ui/live-feed.js`, `live-effects.js`, `telemetry.js`, `sim/traffic.js`, `world/holes.js`, `site/pay.js` or the server's `live` module: skill `replay-test`, and look at its screenshots.

## Detail

- **Live board – who is online, what is on the road, the history** (`docs/replay-and-donations/index.html` → "Online and history"): `GET /api/live` counts the polling page (`?visitor=&page=landing|lobby` – `site/presence.js` gives every page one random id; ≤ 3 ids per client IP; the session cookie, read by `OptionalSessionGuard`, makes it a signed-in player) and returns `online { total, browsing, watching, driving, players }` – SOFT numbers in memory (`SitePresencePort` / `ViewerPresencePort`, one app process, a deploy resets them); each live ride carries `viewers` and `signal` (live · paused · weak = no heartbeat for 40 s). **Abandoned rides**: a ride with no heartbeat for `HB_TIMEOUT_MS` (150 s) can never resume (its next heartbeat fails it) – the stale-ride sweeper (`StaleRideScheduler` → `SweepStaleRidesCommand`, every min(30 s, timeout / 3), AppModule only) ends it as *failed · heartbeat lost* under the owner's player lock (a racing heartbeat / `/end` wins via the optimistic version, the sweep skips); analytics `ended_by=stale_sweep`. **Closing a page is seen at once** (the timeouts are only the fallback for crashes / lost networks): on `pagehide` the landing / lobby / watch page send their poll once more with `&leave=1` (`leaveOnClose` in `site/presence.js`, a `keepalive` fetch → `presence.leave`), and the game sends `navigator.sendBeacon` to `/api/rides/:id/end` (abandoned, "the driver closed the game") with a `text/plain` body – no CORS preflight; `beaconBodyMiddleware` (`infrastructure/http/middleware`) parses it as JSON for that route only, the session cookie authenticates it as usual. **History**: `GET /api/replays?before=<cursor>&limit&wallet&status` (public) – every ride that started and ended, newest end first, a stable `(endedAt, seq)` cursor (index `(status, endedAt)`), the fail CODE (never the reason text), `replay` = a recording is kept. UI: the lobby's header chip `N online · M on the road`, LIVE tab (👁 viewers, PAUSED / WEAK SIGNAL, sort + route filter, ▶ WATCH / WATCH A RANDOM ONE = join), REPLAYS tab (`site/lobby-replays.js`: everyone / mine, the outcome, load more, ▶ REPLAY); the landing's chip `N ONLINE · M ON THE ROAD`, LIVE NOW (👁), RECENT RIDES (▶ REPLAY), 2 × 2 boards. Harness: `server/scripts/sim-rides.mjs` (fake drivers – driving / paused / abandoning / completing, with real chained recordings –, visitors and watchers, each from its own X-Forwarded-For; a CLI and a module) and `server/scripts/e2e-live-board.mjs` – the `live-board-test` skill / `e2e.sh board` (`TRUST_PROXY=1 HB_TIMEOUT_MS=15000`); closing pages = `server/scripts/e2e-close.mjs` (`e2e.sh close` one origin, `close-split` = landing / lobby on `app.localhost`, game on `ride.app.localhost`, API on `api.app.localhost`: the landing / lobby / watch page leave, a closed game tab ABANDONS, Back = a back/forward-cache restore that reloads (`pageshow` in `online.js`), a complete shift closed by its tab = COMPLETED + VERIFIED). A close while the page is still booting can lose the beacon – the 30 s window catches it.
- **Live streams** (spectators; docs/solana-features-plan.md F1; explainer `docs/replay-and-donations/index.html` – keep its numbers in step with `live-rules.ts` / `client/js/watch.js`): `play.html?watch=<rideId>` (`js/watch.js` + `js/ui/watch-panel.js`) replays ANY started ride – live (~`LIVE_LAG` 25 s behind: the verified-play batches are the stream, no WebSockets – everything is a poll) or, once it ended, as a replay with 1/4/16× and a timeline while its recording is kept (`TELEMETRY_RETENTION_DAYS`). The road is rebuilt from seed + route and its holes are the SERVER's obstacle plan (`js/road-plan.js`, `GET /api/watch/:id/road`) – never anything the driver's game reported; each watched batch carries `road` (what the truck did at the planned holes: hit / avoided / ignored, expected vs lost hull) and the replay rings an ignored hole red (self-lit decal), marks it on the timeline (red; hits amber; click = jump), prints `ROAD CHECK · … NO IMPACT` in the panel and stamps NO IMPACT as it passes one; `st` is written from the 10 Hz samples (four columns APPENDED for this: clock hour + the `FLAGS` switches bitmask in `js/telemetry.js` + the INPUT bitmask (`js/input-bits.js`: one frozen bit per control – W and ↑ are both GAS – plus MOUSE (bit 25) for a dash click; controls appended after `mute` skip bit 25, so `map` (key N, dash button `map`) = 1 << 26 – old recordings' N bit is `night`; held at the sample OR pressed since the one before, so a tap shorter than 100 ms still shows) + column 15 = which road of a FORK the truck is on (0 / 1, 0 outside a fork; its s / d are measured on that road; `SAMPLE_FORK_COL`, never judged – `watch.js` switches the drawn road with it, `roads.setBranch`, and never interpolates s / d across a switch) – the verdict reads only the first 12; append, never insert). The replay draws the inputs as **flashing yellow borders** (`cockpit/inputs.js`): a dash control is outlined where it sits (a click adds a pointer + ring), keys show as caps in the lower left of the windscreen (Q W E / A S D / ⇧ always, the others while lit); `watch.js` ORs every sample the playhead passed in a frame (16× skips none) and the lights fade over 0.45 wall s. The raw input events (ms timing – the verdict's human-likeness check) are still never served; spectators get only the per-sample mask. **Traffic** is recorded at 2 Hz beside each batch (`trafficSnapshot()` in `sim/traffic.js`: the nearest ≤ 16 within 400 m as world poses; a batch body field OUTSIDE the canonical hashed text, never judged, dropped – never refused – when malformed or too big) and redrawn by `drawTraffic` (the traffic SIM stays off in a replay, `CFG.TRAFFIC = false`). Not replayed: cracks, debris, the radio. A replay never runs the sim, so whatever the sim would fade (shake, red hit flash) `stepWatch` fades itself. **Feature flags** (server env, `docs/configuration.md`): `LIVE_CHAT` all|free|off · `LIVE_DONATIONS` on|off · `LIVE_FREE_DONATIONS` on|off · `LIVE_EFFECTS` all|free|off ('free' = only on free test rides); code defaults all/on/on/all, **prod compose all/on/off/free**; resolved per ride in `domain/live/live-features.ts`, enforced by `LiveAccessService` (403 `live_feature_off`), sent as `features` in the watch poll + the inbox – the panel and the CB show only those. **Donations**: mock (`POST /api/watch/:id/donations`, nothing charged) or – `LIVE_FREE_DONATIONS=off` – PAID: `POST /api/watch/:id/donation-orders` builds an unsigned devnet SOL transfer FROM the spectator TO THE DRIVER (memo `fc-donation:<order>`), the wallet signs + sends it (`site/pay.js signAndSend`), `…/donation-orders/:orderId/confirm {signature}` verifies it (`verifyDonation`), CLAIMS the order with one conditional update (signature unique) and only then creates the feed event (a new id – cursors never skip it); money that moved is never refused – a lost effect window, effects off or an ended ride deliver it as a tip saying why. Effects: `tip`, `night` / `day` (the driver's `setNight`), `potholes` / `trench` / `sinkhole` = a hole (`placeHole` in `world/holes.js`) in the driver's lane ~940 m ahead, sign first; the driver's stamp (`POST /api/rides/:id/effects/:eventId/applied {t, s, lat, missed?}`, owner, player row lock, first wins; `missed` = no room → `applied.placed:false`) is where it went, so every replay puts it there. Rate limits (429 + `Retry-After`): game effects keep a SLIDING 20 s gap per ride under a per-ride advisory lock, chat lines / mock tips one per wallet per 3 s bucket (unique `(rideId, slotKey, slot)`). **Chat safety**: the driver mutes a wallet (`POST /api/rides/:id/mutes {wallet, muted}`, owner, player lock; `live.RideMute`; the muted wallet can't post there, its lines vanish from every feed via `withoutMuted`, its notes blank) from a MUTE button on each CB line, and folds the CB with K / a click on its header. The watch poll takes `since` (stamps that came after the cursor moved on); sign-in on `ride.<apex>` gets a message naming that host (`rules.gameOrigin`); viewers counted per client IP (≤ 3 ids each). `/api/live` rows + recent finishes carry the ride `id` (the WATCH / replay links on the landing ticker, LIVE NOW board and the lobby's Live tab). Stored in `live.RideEvent` (+ `signature`), `live.DonationOrder`, `live.RideMute` – kept with the ride, not swept. Tests: `server/scripts/e2e-watch.mjs` (LIVE ride, 2 Chromes – CB chat, fold, mute, effects), `e2e-replay.mjs` (a FINISHED ride from the landing's ticker – speeds, seeks across a paid night, the paid hole and the traffic from history, a dash click replayed as a click), `e2e-live-flags.mjs` (production's flags with a fake wallet asked to sign the transfer to the driver; everything off) – the `replay-test` skill runs all three on a throwaway database; the deploy smoke checks the watch API and the game-host sign-in. Open: paid donations whose page closed before confirm (no chain watcher for donations yet, plan F8), a real Phantom on `ride.*`. **Cosmetics**: the watch payload's `ride.loadout` is what the driver wore when the ride STARTED (`Ride.loadout`, docs/garage.md) – `watch.js` calls `setLoadout` on the first poll, so a spectator / replay draws the driver's real cockpit (wheel, paint, shifter, dice, needles).
