## Search + AI crawlers

The pages are static HTML, so crawlers without JavaScript (most AI crawlers) read the real text; the live numbers are `–` until the API answers (never `0`, an AI summary would quote it).
- **One URL per page**: `https://freightchain.fun/` (landing), `https://whitepaper.freightchain.fun/` (whitepaper), `https://ride.freightchain.fun/play.html` (game, `?watch=` links fold into it; no `og:url` there so a shared watch link keeps its own URL). Written out as production URLs on purpose – a staging copy then points search at production. nginx 301s the duplicates (the `fc-seo` snippet in `deploy/scripts/remote/setup.sh`: `ride.<apex>/` → apex, `<apex>/whitepaper.html` → whitepaper host; `deploy/nginx/www.conf.template`: `www.` → apex). The static HTML never links a URL that redirects (search lists each as "page with redirect"): the landing's whitepaper / pitch-deck links and the whitepaper's links to the landing, game, lobby and viewer are written as production URLs, and `main.js` / `whitepaper.js` point them at this origin when `hosts.js` is not split (`seo.test.js`). `http://`, `www.` and `ride.<apex>/` stay in that report for good – correct 301s.
- **noindex**: `client/lobby.html`, `client/viewer.html` (storybook host), `client/admin.html`. robots.txt blocks only `/api/` – a Disallowed page's noindex is never read.
- **`landing/public/`** (Vite copies it to the root of `dist/`, served on every host): `robots.txt` (all open but `/api/`, AI crawlers named – GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended… – and the absolute `Sitemap:` line, which also authorises the sitemap's cross-host URLs), `sitemap.xml` (the three canonical URLs, no `lastmod`), `llms.txt` (summary + links for AI assistants; the same one-line description as the JSON-LD), `indexnow-key.txt` (public by design; `deploy/scripts/indexnow.mjs` pings IndexNow – Bing, Yandex… – after every deploy, `--dry-run` to see what it would send).
- **JSON-LD**: the landing has `Organization` (+ `sameAs` = the X / YouTube / GitHub links the page shows) + `WebSite` + `VideoGame`/`WebApplication` (free offer); the whitepaper a `TechArticle` about that game. Never add an `aggregateRating` or review that does not exist. Validate with Google's Rich Results Test after a change.
- **Budget**: with the JSON-LD and 31 badge cards the whitepaper is 34.0 of its 34 kB gz (42 bytes left, Oct 14) (`test/budget.test.js`) – prune before growing it.
- **Outside the repo** (one-time, by hand): Google Search Console **Domain property** (DNS TXT – covers every subdomain), submit the sitemap; Bing Webmaster Tools → import from Search Console; a `www` A record, then `npm run deploy:setup`. Check with `site:freightchain.fun` on Google and Bing, URL Inspection, and a link pasted into X / Discord.

## App icon (browser tab, Phantom / wallet connect, home screen)
Chosen design = **Solana Road** (road to a purple glow, lane marks in the Solana gradient); the other nine candidates incl. **Horizon** stay in `design/icons/` (SVG + 1024 px PNG, `gen.mjs` regenerates them). `node design/icons/build-app-icons.mjs` (needs Chrome + macOS `sips`) writes the shipped set into `client/`: `favicon.ico` (16/32/48), `icons/{icon.svg, icon-192, icon-512, maskable-512, apple-touch-icon, favicon-32}`, `manifest.webmanifest`. Fixed root paths on every host (the apex, `ride.*`; the landing build does not shadow them); every page's `<head>` links them (`landing/index.html`, `client/{lobby,play,viewer}.html`; `landing/test/page.test.js` checks the files exist). **Phantom shows no logo from code: it reads the page's own favicon / apple-touch-icon of the origin you connect from** – so these links are the "wallet logo". Wallets cache the icon; a new one can take a while to appear. To switch design: edit `build-app-icons.mjs`, rerun, commit the output.
