# Admin page, logs, observing production – detail

Agent reference, moved verbatim out of `AGENTS.md` (which keeps only the map and the hard rules and is loaded into every agent session); an "In short" block, where there is one, is a summary. Read the file for a topic before changing it; keep it current like AGENTS.md ("Maps stay current").

## In short

- **Admin page** (`frontend/client/admin.html` + `site/admin.js`, `admin.<apex>` behind nginx basic auth; player-facing `docs/tech/verified-play/index.html`; spec: `docs/spec/admin_security.md`): its own security zone. `AdminGuard` takes only the ADMIN session (`fc_admin` from `/api/admin/auth/*`, `AdminTokenPort`, `ADMIN_JWT_SECRET`, wallets in `ADMIN_WALLETS`) – never the player's session (`fc_session`, `__Host-fc_session` in production) – and on a split deployment only `Host` = `admin.<COOKIE_DOMAIN>` (read `headers.host`, never `req.hostname` / `X-Forwarded-Host`); POSTs need `X-FC-Admin: 1`. Every admin change needs a wallet signature over `POST admin/rides/:id/challenge`'s text (`AdminProofService`, single use, 5 min) and is audited (`admin.AdminAction`). New admin routes: guarded by default (`@AdminPublic()` only for the sign-in), changes signed + audited. Tests: `loginAdmin` (`test/support/client.ts`), `testAdmin` (`test/support/admin-fixtures.ts`), the fake Phantom in `backend/server/scripts/e2e-admin.mjs`. Local without Phantom: `ADMIN_WALLETS=64GheTAtcPoz6Re29qwWxzKU2gtZCTF6gC1NBPVgaL2N` in `backend/server/.env` + the DEV WALLET (local) button (`site/dev-wallet.js`, localhost only, a public test key; the server verifies the signatures as always) – never in `infra/deploy/.env`.
- **Observing production (read-only)**: `npm run ops -- logs|nginx|query|sql|ps` (`infra/deploy/scripts/ops.sh`) and the project skills in `.claude/skills/` – the index with the command for each is `README.md` → "Skills" (per-skill notes below). They never deploy or write production. `run-tests/e2e.sh` builds the server and the landing into PRIVATE copies (`backend/server/.e2e-build-<pid>/`, gitignored, removed at the end) so another session's build cannot empty `backend/server/dist` / `frontend/landing/dist` mid-run. **Worktrees share the compose PostgreSQL and its `freightchain_test` database** – a branch with other migrations makes the drift check fail; give it its own: `TEST_DATABASE_URL=postgresql://freight:freight_dev_password@localhost:15433/freightchain_<branch>_test npm run server:integration` (created + migrated automatically; the name must end in `_test`).

## Detail

- **Admin page views & routes**: overview, review queue (`?review=under_review[&pool=N]`: every completed PAID ride under review first – with its pool –, then the flagged free rides → accept / reject = `VerdictService.override`, or RE-JUDGE at the current rules = `VerdictService.rejudge`; an unjudged completed shift can be judged from there too; under the player lock, audited in `admin.AdminAction`; re-judging never replaces it), rides (incl. `REPLAY VERIFICATION` section showing 10 Hz replay sessions + `RideReplayFlag` red flags on `#ride/<id>`), REPLAYS (`#replays`, `GET /api/admin/replays[?status=&limit=]`: `{ queue: { kind, depth }, rows: RideReplayDto[] }` for recent `verdict.RideReplay` sessions and red flags), PLAYERS / PAYOUTS (`site/admin-pools.js`, `admin-pools.http.controller.ts`: `GET pool-payouts` = every live / recently settled pool with its winners list (`GetPoolStandingsQuery`), the payout job's state and the hold; HOLD / RELEASE = `POST pools/:id/hold/challenge` → signed `POST pools/:id/hold`, audited `pool.hold` / `pool.release` – the payout job pays nothing while held) · POOLS / STATS / SESSIONS (`site/admin-directory.js`, `admin-directory.http.controller.ts` + `AdminDirectoryPort`: read-only – `GET players[?q=<wallet prefix>]`, `players/:wallet` (balances, statistics, tickets + ledger, payments, latest rides + sign-ins), `pools[/:id]` (the on-chain mirror and its holders – nothing here changes a pool, the money is in the program), `stats` (global + days + top riders; `stats:reconcile` repairs), `sessions?days=` (wallets that signed in inside the window; sessions are stateless JWT cookies, so there is still no revoke)), SETTINGS (`site/admin-settings.js`: the `GameSetting` knobs and one wallet's free rides – signed via `settings/challenge` / `players/free-rides/challenge`; `#settings/<wallet>` prefills the wallet), sign-ins (`player.SignIn`: wallet, time, IP, browser – sessions are JWT cookies, no session table, not revocable one by one), the in-memory log ring (`JsonLogger`, last 5000 lines – see `docs/agents/repo.md`), audit. `backend/server/scripts/e2e-admin.mjs` drives it.
- **Skills reference** (`.claude/skills/`, full command table in `README.md` → "Skills"): `prod-logs`, `prod-db`, `ride-investigate`, `localnet-e2e` (`npm run test:localnet`: the REAL money flows on a local `solana-test-validator` with the verifiable `.so` + the server in program mode on a throwaway DB – purchases, verified ticket rides, refunds, payouts, close_pool, every lamport asserted; then TEN riders on one pool; then THE AUTONOMOUS DAY of program v2 – and a coverage gate: every instruction / event on the validator, every error code asserted; ~16 min, `SCENARIO=money|payout|day|chaos`; explainer: `docs/tech/localnet-e2e/index.html`), `program-check` (the escrow program: `solana-verify` reproducible Docker build vs the committed `verifiable-build.hash`, the LiteSVM tests on that exact `.so`, IDL drift, clippy, `cargo audit`, then the Trail of Bits Solana scanner + `review-checklist.md`; `check.sh onchain` = read-only deployed-hash compare; never `verify-from-repo`, it writes on chain), `run-tests` (the whole test pyramid + real-Chrome e2e on a throwaway database – there is no CI), `test-census` (`npm run test:census` prints the pyramid; `npm run test:census -- features` the coverage by feature, user flow, controller and route (map: `.claude/skills/test-census/features.mjs`); `npm run test:census -- coverage` records v8 line + branch coverage; `npm run test:census -- run` records timings, and `run e2e…` the routes each browser suite hit; `npm run test:census -- readme` rewrites the README Tests block and `docs/testing/test-coverage.md`), `replay-test` (live streams, replays and the LIVE_* flags e2e: a driver + a spectator Chrome), `live-board-test` (online / on the road / the replays history, fed by the ride simulator), `stats-reconcile` (`bash .claude/skills/stats-reconcile/run.sh [--fix|--prod]`: recompute the statistics from the rides, report drift, local `--fix`, production read-only), `posthog-test` (local analytics smoke), `posthog-prod` (read-only production ingest check), and `analytics-review` (three local passes over the landing, whitepaper, lobby, and the online ride — `node .claude/skills/analytics-review/inventory.mjs`; The admin alert banner wraps wallet/target text and scrolls within 220px so narrow screens retain access to the navigation and ride details; the admin Chrome suite checks both bounds.

The signed settings table includes `referral_count_weekly_grant` (0/1, default 1). It controls whether a weekly grant at trust 100 can count toward Convoy milestones; it never makes grants emit ride TEN4.
