# Admin page, logs, observing production – detail

Agent reference, moved verbatim out of `AGENTS.md` (which keeps only the map and the hard rules and is loaded into every agent session); an "In short" block, where there is one, is a summary. Read the file for a topic before changing it; keep it current like AGENTS.md ("Maps stay current").

## In short

- **Admin page** (`client/admin.html` + `site/admin.js`, `admin.<apex>` behind nginx basic auth; player-facing `docs/verified-play/index.html`): its own security zone. `AdminGuard` takes only the ADMIN session (`fc_admin` from `/api/admin/auth/*`, `AdminTokenPort`, `ADMIN_JWT_SECRET`, wallets in `ADMIN_WALLETS`) – never the player's session (`fc_session`, `__Host-fc_session` in production) – and on a split deployment only `Host` = `admin.<COOKIE_DOMAIN>` (read `headers.host`, never `req.hostname` / `X-Forwarded-Host`); POSTs need `X-FC-Admin: 1`. Every admin change needs a wallet signature over `POST admin/rides/:id/challenge`'s text (`AdminProofService`, single use, 5 min) and is audited (`admin.AdminAction`). New admin routes: guarded by default (`@AdminPublic()` only for the sign-in), changes signed + audited. Tests: `loginAdmin` (`test/support/client.ts`), `testAdmin` (`test/support/admin-fixtures.ts`), the fake Phantom in `server/scripts/e2e-admin.mjs`. Local without Phantom: the DEV WALLET button + its public key in `server/.env` `ADMIN_WALLETS` – never in `deploy/.env`.
- **Observing production (read-only)**: `npm run ops -- logs|nginx|query|sql|ps` (`deploy/scripts/ops.sh`) and the project skills in `.claude/skills/` – the index with the command for each is `README.md` → "Skills" (per-skill notes below). They never deploy or write production. `run-tests/e2e.sh` builds the server and the landing into PRIVATE copies (another session's build empties `server/dist` / `landing/dist`). **Worktrees share the compose PostgreSQL and its `freightchain_test` database** – a branch with other migrations makes the drift check fail; give it its own: `TEST_DATABASE_URL=postgresql://freight:freight_dev_password@localhost:15433/freightchain_<branch>_test npm run server:integration` (created + migrated automatically; the name must end in `_test`).

## Detail

- **Admin page** `client/admin.html` + `site/admin.js` (`admin.<apex>` behind nginx basic auth – `DEPLOY_ADMIN_USER` / `DEPLOY_ADMIN_PASSWORD` in `deploy/.env`; `/admin.html` elsewhere redirects there; `/api/admin/*`, `AdminGuard`: on a split deployment only when `Host` = `admin.<COOKIE_DOMAIN>` (never `req.hostname` / `X-Forwarded-Host`), then an **admin session** – its own wallet sign-in on the page (`POST /api/admin/auth/{nonce,verify,logout}`: an ADMIN sign-in message, SIWS format with the admin host as domain, only for `ADMIN_WALLETS`) → the `fc_admin` cookie (`AdminTokenPort`: own key `ADMIN_JWT_SECRET`, audience `admin`, `ADMIN_SESSION_TTL_MINUTES` 120; httpOnly, SameSite=Strict, Path `/api/admin`, no Domain) – the player session grants nothing there – and the wallet still in `ADMIN_WALLETS`, else 404; POSTs need the `X-FC-Admin: 1` header; **every change is signed**: `POST rides/:id/challenge` → the wallet signs the text for exactly that change → the change carries the signature (`AdminProofService`, `domain/admin/admin-proof.ts`; single use, 5 min; the audit row keeps text + signature)): overview, review queue (`?review=under_review[&pool=N]`: every completed PAID ride under review first – with its pool –, then the flagged free rides → accept / reject = `VerdictService.override`, or RE-JUDGE at the current rules = `VerdictService.rejudge`; an unjudged completed shift can be judged from there too; under the player lock, audited in `admin.AdminAction`; re-judging never replaces it), rides (incl. `REPLAY VERIFICATION` section showing 10 Hz replay sessions + `RideReplayFlag` red flags on `#ride/<id>`), REPLAYS (`#replays`, `GET /api/admin/replays[?status=&limit=]`: `{ queue: { kind, depth }, rows: RideReplayDto[] }` for recent `verdict.RideReplay` sessions and red flags), PLAYERS / PAYOUTS (`site/admin-pools.js`, `admin-pools.http.controller.ts`: `GET pool-payouts` = every live / recently settled pool with its winners list (`GetPoolStandingsQuery`), the payout job's state and the hold; HOLD / RELEASE = `POST pools/:id/hold/challenge` → signed `POST pools/:id/hold`, audited `pool.hold` / `pool.release` – the payout job pays nothing while held) · POOLS / STATS / SESSIONS (`site/admin-directory.js`, `admin-directory.http.controller.ts` + `AdminDirectoryPort`: read-only – `GET players[?q=<wallet prefix>]`, `players/:wallet` (balances, statistics, tickets + ledger, payments, latest rides + sign-ins), `pools[/:id]` (the on-chain mirror and its holders – nothing here changes a pool, the money is in the program), `stats` (global + days + top riders; `stats:reconcile` repairs), `sessions?days=` (wallets that signed in inside the window; sessions are stateless JWT cookies, so there is still no revoke)), SETTINGS (`site/admin-settings.js`: the `GameSetting` knobs and one wallet's free rides – signed via `settings/challenge` / `players/free-rides/challenge`; `#settings/<wallet>` prefills the wallet), sign-ins (`player.SignIn`: wallet, time, IP, browser – sessions are JWT cookies, no session table, not revocable one by one), the in-memory log ring, audit. `server/scripts/e2e-admin.mjs` drives it. **Local without Phantom**: `ADMIN_WALLETS=64GheTAtcPoz6Re29qwWxzKU2gtZCTF6gC1NBPVgaL2N` in `server/.env` + the DEV WALLET (local) button (`site/dev-wallet.js`, localhost only, a public test key; the server verifies the signatures as always) – never in `deploy/.env`.
