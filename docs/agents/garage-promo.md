# Garage + promo codes – rules

Agent reference, moved verbatim out of `AGENTS.md` (which keeps only the map and the hard rules and is loaded into every agent session); an "In short" block, where there is one, is a summary. Read the file for a topic before changing it; keep it current like AGENTS.md ("Maps stay current").

- **Garage** (`docs/garage.md`): the lobby tab with the parts catalog (5 slots), the REAL cockpit canvas (`site/garage-cab.js`) and APPLY (`POST /api/garage/loadout`, all-or-nothing, one transaction → `player.CosmeticEquip`). A new part / slot goes in the server AND client catalogs (drift-tested) with a palette; the defaults must keep drawing the old cockpit (`npm run check`). Tests: garage dto / handler / controller specs, the "garage" scenarios, the lobby e2e – look at `garage-desktop.png` / `garage-phone.png`.
- **Promo codes** (`docs/promocodes.md`): truck-part promo codes are not a feature. One effect per code – tickets or extra free rides (may exceed the daily cap). Creating or redeeming `kind: 'cosmetic'` is refused (`visuals_are_honk`): cab colours are minted by burning HONK (`docs/honk/SPEC.md`). Existing cosmetic unlocks stay wearable; the cosmetic columns stay so an old row still loads. Created / disabled on the admin page, **signed + audited** (every field is in the signed text – a new field goes into `promoJson` too). Redeeming runs under the player lock and refuses BEFORE it uses a redemption; its own per-IP budget `THROTTLE_PROMO_LIMIT`. Cosmetics catalog `server/src/domain/economy/cosmetics.ts` ⇄ `client/js/cosmetics.js` (leaf, palettes in `LOOKS`, drift-tested). A promo link only PRE-FILLS the code. Promo analytics never carry free text. A change needs its migration, unit + scenario + integration + concurrency tests, and the lobby / admin / `promo` / `wallet` + `wallet-split` e2e suites.
