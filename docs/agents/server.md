# Server rules, checks, configuration – detail

Agent reference, moved verbatim out of `AGENTS.md` (which keeps only the map and the hard rules and is loaded into every agent session); an "In short" block, where there is one, is a summary. Read the file for a topic before changing it; keep it current like AGENTS.md ("Maps stay current").

- **Server rules (docs/backend-architecture.md, enforced by `server/test/architecture`)**:
  - Layers point inward: `domain` is pure (entity classes `Ride`/`Player`/`Round`/`Payment`… – rules live in their methods), `application` = abstract-class ports + CQRS handlers + services, `infrastructure` implements the ports, `presentation` = thin controllers. Prisma rows ⇄ entities only in `infrastructure/prisma/mappers`.
  - HTTP: every request part through `@ZodBody/@ZodQuery/@ZodParams`; every route returns a typed, non-empty DTO **produced through the bus** (`commandBus`/`queryBus.execute`); no Nest `HttpException` – throw `DomainError`s, the one `ProblemDetailsFilter` renders RFC 9457 problem+json; every response has `X-Request-Id`.
  - Every timestamp from `ClockPort` (rows, JWTs, cookies – only `infrastructure/time/system.clock.ts` reads the wall clock); `process.env` only in `infrastructure/config/` (`EnvService`); files ≤ 500 lines.
  - **Race-safety is part of the design**: anything a wallet does to its rides / credits / payments / tickets runs in a transaction under `findByWalletForUpdate` (the player row lock); rounds are locked when paid into or closed; aggregates use optimistic versions. **Lock order with pools: player row → pool row (`findByIdForUpdate`) → ticket rows**, never the other way round. A new critical section needs a test in `test/integration/concurrency.integration.spec.ts`.
  - **A Prisma schema change needs a migration in the same change** (forward-only SQL; `test/integration/migrations.integration.spec.ts` fails on drift).
  - **The test pyramid is mandatory** (`test/architecture/test-pyramid.spec.ts`, no allow-list): every new controller, CQRS handler, service, guard, interceptor, filter or adapter ships with its own unit spec (`test/unit/**/<file>.spec.ts`), every class that talks to PostgreSQL with its own integration spec (`test/integration/**/<file>.integration.spec.ts`); new behaviour also gets an HTTP scenario in `test/scenarios/` (runs on in-memory AND PostgreSQL).
  - Rate limits (`THROTTLE_LIMIT` per signed-in wallet or IP, `THROTTLE_AUTH_LIMIT` on `/api/auth/*`) count per IP correctly only with `TRUST_PROXY` set – production requires it, with `JWT_SECRET` and `TREASURY_PUBKEY`.

- Server checks: `npm run server:test` (Docker-free: controller / handler / service / domain / infrastructure unit specs, architecture + pyramid audits, migration SQL, the whole HTTP surface on in-memory repositories) and `npm run server:integration` (Docker: repository specs, the same HTTP scenarios on real PostgreSQL, concurrency, schema drift – in its own `freightchain_test` database; a worktree whose migrations differ from another's must use its own: `TEST_DATABASE_URL=…/freightchain_<branch>_test`). The server mirrors `MAX_SPEED` / `COMPLETE_DIST_K` / the route ids in `server/src/domain/rides/ride-rules.ts` – keep them equal to `client/js/config.js` and `client/js/themes`.

## Configuration (full human guide: `docs/configuration.md`)

- **Sources of truth**: server env = `server/src/infrastructure/config/env.schema.ts` (zod; read ONLY through `EnvService`); game tunables = `client/js/config.js` (`CFG`); URLs = `client/js/hosts.js`; verdict thresholds = `server/src/domain/verdict/verdict-rules.ts`. Two env files: `server/.env` (dev, from `.env.example`) and `deploy/.env` (production + `DEPLOY_*`, from `deploy/.env.example`) – both gitignored; read key NAMES (`grep -oE '^[A-Z_0-9]+=' file`), never print values. PostHog differs between them: local `POSTHOG_ENABLED=0`, production `POSTHOG_ENABLED=1`.
- **A new server setting touches four places**: `env.schema.ts`, `server/.env.example`, `deploy/.env.example`, **and the `app.environment` block of `deploy/docker-compose.prod.yml`** – the container only gets keys listed there, so a key present in `deploy/.env` but missing from compose is silently ignored. A generated secret also goes into `deploy/scripts/init-env.mjs`; one that is `optional()` in the schema needs the `KEY=` → unset handling the schema already provides.
- **Runtime settings are rows, not env**: `player.GameSetting` holds `free_on_signup`, `free_rides_daily_max`, `offline_free_rides`, `offline_free_rides_per_ip`. A missing or out-of-range value falls back to the code default. Change one with the signed admin settings API. Do not add an env key for them. See `docs/configuration.md` → "Runtime settings".
- **Derived, never typed**: `APP_DOMAIN`, `APP_ORIGIN`, `APP_PORT`, `COOKIE_DOMAIN`, `CORS_ORIGINS` come from `DEPLOY_DOMAIN` (`deploy/scripts/lib.sh` `app_env`). `DEPLOY_*` stay local. Production requires `JWT_SECRET`, `TREASURY_PUBKEY`, `TRUST_PROXY=1`; Solana is devnet-only (`validate-env.mjs` asks the RPC for its genesis hash).
- **Defaults differ between code and prod**: `VERDICT_ENFORCE` code `true` / prod compose `false` (shadow mode); `RIDE_MIN_SECONDS` 300 is a test value (prod 1800); `JWT_SECRET` unset in dev = random per boot; `TREASURY_PUBKEY` unset in dev = `server/data/treasury.json`.
- **Secrets** (`JWT_SECRET`, `ADMIN_JWT_SECRET`, `WEBHOOK_SECRET`, `CRANK_SECRET`, `POSTGRES_PASSWORD`, `DEPLOY_ADMIN_PASSWORD`, `POSTHOG_KEY` (project token `phc_…` only – a personal `phx_…` is never stored), any `SOLANA_RPC` URL with an API key, `deploy/secrets/*`): never in the chat, a commit, a log or an example file; `*.example` files hold dummies only. `POSTHOG_PROJECT_ID` (297915) is not a secret.
- **Test / tool env vars** (`TEST_DATABASE_URL`, `BASE`, `PORT`, `CHROME_PORT`, `CHROME`, `SHOTS`, `ADMIN_KEYPAIR`, `SMOKE_ADMIN_AUTH`, `DEPLOY_ENV_FILE`, …) are tabulated in the guide; Chrome debug ports are shared between sessions – set `PORT` / `CHROME_PORT` when another session may be running.
- **Browser state** that looks like config (`localStorage` `freightchain.*`: assist, level (the free level picked in the lobby), truck tuning, radio, admin, and `freightchain.anon`) lives in the player's browser – a stale value explains "only broken in my browser".
- Known drift is listed at the bottom of `docs/configuration.md`; when you fix or add a key, update that page in the same change.
