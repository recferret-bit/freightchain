# Server rules, checks, configuration – detail

Agent reference, moved verbatim out of `AGENTS.md` (which keeps only the map and the hard rules and is loaded into every agent session); an "In short" block, where there is one, is a summary. Read the file for a topic before changing it; keep it current like AGENTS.md ("Maps stay current").

- **Server rules (`docs/tech/backend-architecture.md`, enforced by `backend/server/test/architecture`)**:
  - Layers point inward: `domain` is pure (entity classes `Ride`/`Player`/`Round`/`Payment`… – rules live in their methods), `application` = abstract-class ports + CQRS handlers + services, `infrastructure` implements the ports, `presentation` = thin controllers. Prisma rows ⇄ entities only in `infrastructure/prisma/mappers`.
  - HTTP: every request part through `@ZodBody/@ZodQuery/@ZodParams`; every route returns a typed, non-empty DTO **produced through the bus** (`commandBus`/`queryBus.execute`); no Nest `HttpException` – throw `DomainError`s, the one `ProblemDetailsFilter` renders RFC 9457 problem+json; every response has `X-Request-Id`. Solana Actions (`/actions.json`, `/.well-known/actions.json`, `/api/actions/*`) are the exception: CORS `*` with no credentials, `X-Action-Version: 2.4`, devnet chain id `solana:EtWTRABZaYq6iMfeYKouRu166VU2xqa1`, and `ActionErrorFilter` answers `{ message }`. A buy is one program-mode ticket and still needs both profile stamps. `GET/POST /api/actions/hello` (actions.json `/hello`) is a static one-button card: the POST is `{ type: 'post', message: 'Hello.' }` and signs nothing. Every `external-link` button's `href` is an action route (`POST /api/actions/go/home|live`, `/api/actions/ride/:id`, `/api/actions/ride/:id/watch`) answering `{ type: 'external-link', externalLink }` – blink clients POST to every href, never to a page. Payload shapes are type-checked against the vendored spec (`test/support/actions-spec.d.ts`); `/blink.html` renders the cards while dial.to is paused.
  - Every timestamp from `ClockPort` (rows, JWTs, cookies – only `infrastructure/time/system.clock.ts` reads the wall clock); `process.env` only in `infrastructure/config/` (`EnvService`); files ≤ 500 lines.
  - **Race-safety is part of the design**: anything a wallet does to its rides / credits / payments / tickets / pledges runs in a transaction under `findByWalletForUpdate` (the player row lock); rounds are locked when paid into or closed; aggregates use optimistic versions. **Lock order with pools: player row → pool row (`findByIdForUpdate`) → ticket / pledge rows**, never the other way round. A new critical section needs a test in `test/integration/concurrency.integration.spec.ts`.
  - **Program v3 on the server** (detail: `docs/spec/pool.md`): the road seed is the pool's on-chain `seed_commitment` (the program commits it from SlotHashes; `domain/road/provable-seed.ts` projects it and packs the preimage for a verifier); `AttestationService` writes the payout key's attestation (RFC 6962 root of the ride's batches, `domain/telemetry/telemetry-merkle.ts`) for winners and pledged drivers; pledges are rows that follow the chain – `CreatePledgeHandler` (unsigned `create_pledge`), `ConfirmPledgeHandler` (the transaction's own PledgeCreated), `SyncPledgesHandler` (settle / refund with the payout key, after every payout pass). No endpoint moves pledge money or marks a pledge settled.
  - **Native SIWS & SNS identity**:
    - Native Sign-In With Solana: `backend/server/src/application/use-cases/auth/verify-signin` validates 1-click `solana:signIn` and standard `signMessage` challenges via Ed25519; single-use nonces are burned immediately (`nonce:${nonce}`). Like `verifySignIn` of `@solana/wallet-standard-util`, every field the stored challenge set (domain, statement, URI, version, chain id `solana:devnet`, issued / expiration time) must come back unchanged in the signed text. The challenge names the app, or the game host when Origin is that page. Outside production it names a page on `localhost`, `127.0.0.1`, `::1` or `*.localhost` instead. Production does not. A desktop with no extension opens `POST /api/auth/pair` (a 3-minute code, secret in the httpOnly `fc_pair` cookie, not in the QR). The phone signs in and `POST /api/auth/pair/:id/claim` stores that session; the desktop's `GET` adopts it and the row is deleted. A phone browser is sent into the wallet app instead of a QR.
    - Solana Name Service (SNS): `backend/server/src/infrastructure/sns/sns-name-service.adapter.ts` queries Mainnet-Beta RPC (`SNS_RPC`) for favorite/reverse `.sol` domain PDAs with 24h positive / 30m negative caching; enriches player profiles and public board DTOs.
  - **Paid play needs both profile agreements.** `Player.age18At` and `Player.lossAt` (null = off). `PUT /api/profile/agreements` stamps them under the player row lock. A paid ride order, a resume into a paid ride, a non-free start, a ticket order (including handing back the live one) and an unsigned payment or buy transaction are refused with 409 `agreements_required` until both are set. Tutorial / assist on a paid tier, `level_free_only`, `tier_not_on_sale` and a missing treasury still answer first. Confirming SOL already sent is not refused. A direct on-chain `buy_ticket` bypasses the server's transaction builder: settlement still credits the ticket, and start-ride remains the play gate. The Anchor program is unchanged.
  - **A Prisma schema change needs a migration in the same change** (forward-only SQL; `test/integration/migrations.integration.spec.ts` fails on drift).
  - **The test pyramid is mandatory** (`test/architecture/test-pyramid.spec.ts`, no allow-list): every new controller, CQRS handler, service, guard, interceptor, filter or adapter ships with its own unit spec (`test/unit/**/<file>.spec.ts`), every class that talks to PostgreSQL with its own integration spec (`test/integration/**/<file>.integration.spec.ts`); new behaviour also gets an HTTP scenario in `test/scenarios/` (runs on in-memory AND PostgreSQL).
  - Rate limits (`THROTTLE_LIMIT` per signed-in wallet or IP, `THROTTLE_AUTH_LIMIT` on `/api/auth/*`) count per IP correctly only with `TRUST_PROXY` set – production requires it, with `JWT_SECRET` and `TREASURY_PUBKEY`.

- Server checks: `npm run server:test` (Docker-free: controller / handler / service / domain / infrastructure unit specs, architecture + pyramid audits, migration SQL, the whole HTTP surface on in-memory repositories) and `npm run server:integration` (Docker: repository specs, the same HTTP scenarios on real PostgreSQL, concurrency, schema drift – in its own `freightchain_test` database; a worktree whose migrations differ from another's must use its own: `TEST_DATABASE_URL=…/freightchain_<branch>_test`). The server mirrors `MAX_SPEED` / `COMPLETE_DIST_K` / the route ids in `backend/server/src/domain/rides/ride-rules.ts` – keep them equal to `frontend/client/js/config.js` and `frontend/client/js/themes`.

- **3D models (entities)**: the server never runs an entity file – `checkEntitySource` (`domain/entities/entity.ts`) parses it literal-only and validates it with the shared core (`frontend/client/shared/entity/`, reached via `domain/shared/entity.js`). Writes go through `EntityWriteService` only (one transaction, the entity row lock, a `stale_base` 409, append-only revisions); the ONLY thing that changes what players draw is the signed `PublishRevisionHandler` (AdminProofService surface `editor`, audited `entity.publish`). The bundle (`EntityCatalogService`) = the code's seed ⊕ published revisions, held in memory. The AI editor (jobs, the provider adapters, the MCP bridge) runs only in dedicated editor-worker processes over a shared PostgreSQL queue (atomic admission, global parallel cap and non-replayed claims) and writes only through the MCP callbacks (`McpJobGuard`: a running job's token, never through nginx) as drafts. Detail: `docs/spec/platform_services.md`.

## Configuration (full human guide: `docs/tech/configuration.md`)

- **Sources of truth**: server env = `backend/server/src/infrastructure/config/env.schema.ts` (zod; read ONLY through `EnvService`); game tunables = `frontend/client/js/config.js` (`CFG`); URLs = `frontend/client/js/hosts.js`; verdict thresholds = `backend/server/src/domain/verdict/verdict-rules.ts`. Two env files: `backend/server/.env` (dev, from `.env.example`) and `infra/deploy/.env` (production + `DEPLOY_*`, from `infra/deploy/.env.example`) – both gitignored; read key NAMES (`grep -oE '^[A-Z_0-9]+=' file`), never print values. PostHog differs between them: local `POSTHOG_ENABLED=0`, production `POSTHOG_ENABLED=1`.
- **A new server setting touches four places**: `env.schema.ts`, `backend/server/.env.example`, `infra/deploy/.env.example`, **and the `app.environment` block of `infra/deploy/docker-compose.prod.yml`** – the container only gets keys listed there, so a key present in `infra/deploy/.env` but missing from compose is silently ignored. A generated secret also goes into `infra/deploy/scripts/init-env.mjs`; one that is `optional()` in the schema needs the `KEY=` → unset handling the schema already provides.
- **Runtime settings are rows, not env**: `player.GameSetting` holds `free_on_signup`, `free_rides_daily_max`, the six grant knobs `weekly_ticket_{1h,4h,8h}_{enabled,days}` (1h on / 7 days; 4h and 8h off / 7 days), the `editor_*` knobs, and the `referral_*` knobs (invite cap, free-ride grants, the pot cap, the donation share). A missing or out-of-range value falls back to that key's code default. A grant flag is 0 or 1. A grant interval is at least 1 day. Change one with the signed admin settings API. Do not add an env key for them. See `docs/tech/configuration.md` → "Runtime settings" and `docs/spec/referral.md`.
- **Referrals** (`GET /api/referrals`, `POST /api/referrals/bind`, `POST /api/referrals/gift`): the signed-in wallet only. One code, one referrer ever, bind before a ride starts. Detail: `docs/spec/referral.md`.
- **Phone minigames** (`MINIGAMES` = `off` | `shadow` | `enforce`, default `off`): a second signal on 1h paid rides, never a reason to reject one. Only `phone-sms` is issued. Owner routes: `POST /api/rides/:id/minigames/:eventId/open`, `POST .../answer`, `GET .../assets/:assetId`. `mgCommit` is on the start response. `mgSalt` is added on GET ride only after a verdict and only when the mode is not off. Code: `backend/server/src/domain/minigames/`. Spec: `docs/spec/minigames.md` Part 1.
- **Telemetry v2.1** (`TELEMETRY_V21` = `off` | `shadow` | `enforce`, schema default `off`): `off` keeps v1. `shadow` returns a session key and salt commitments from `POST /start`, MAC-checks `protocol: 2` batches (`400 batch-mac-missing` / `batch-mac-invalid`; a bad or oversized stream after that MAC is `400 batch-streams-invalid` / `batch-streams-oversize`), and does not reject v1 batches. Pause and slow-mo are flags, not rejects (`pause-limit`, `pause-time`, `time-dilation`). `enforce` requires the named deflate streams `inp`, `clk`, `chk`, `mg`, and `env`, checks the HMAC before inflate, steps that input with `stepAt30Hz`, compares `worldDigest32` (a mismatch of at least 10 s after three points in a row rejects; a shorter mismatch flags), and rejects a fourth pause, more than five minutes paused, or sustained slow-motion. `enforce` also returns the re-derivable traffic and hole salts from `POST /start`. The live `ReplayEngine` stays at `REPLAY_SIM_HZ` 10. `stepAt30Hz` is not the live replay. `RULES_VERSION` stays 7. `MINIGAMES` stays `off` unless it is `shadow` or `enforce`. Code: `frontend/client/shared/batch-mac.js`, `ride-salts.js`, `physics.js` `stepAt30Hz`, `UploadBatchHandler`, `domain/rides/pause-bounds.ts`.
- **Live 30 Hz cutover (declined, decision 69, 24.10.2026)**: the live `ReplayEngine` stays at `REPLAY_SIM_HZ` 10. `stepAt30Hz` is not the judge. Recorded rides stay on the 10 Hz sample stream. `TELEMETRY_V21` and `MINIGAMES` stay `off`. Do not retune `REPLAY_SIM_HZ`.
- **Browser trust (audit H7 / M4 / M9)**: every POST / PUT / PATCH / DELETE passes `OriginGuard` (global): no Origin, the request's own origin, or `CORS_ORIGINS` – `Origin: null` never; on the admin host only the admin page; `@CrossOriginPublic()` opens Actions, Solana Pay and the chain webhook. The API takes JSON only (`json-only.middleware.ts`: any other body type – a form, text/plain, an `<a ping>` – is 415, the `/end` beacon excepted). The admin host answers no CORS. The storybook host (`EnvService.editorHost`) answers only `/api/entities/*` and `/api/editor/*` (OriginGuard 404s the rest there, any method); its editor POSTs are same-origin. In production the player session is `__Host-fc_session` (host-only on the API host, `EnvService.sessionCookie`); the old apex-wide `fc_session` is expired wherever it still arrives. Every path predicate compares `apiPath()` (lowercase, no trailing slash) – Express routes case-insensitively.
- **Derived, never typed**: `APP_DOMAIN`, `APP_ORIGIN`, `APP_PORT`, `COOKIE_DOMAIN`, `CORS_ORIGINS` come from `DEPLOY_DOMAIN` (`infra/deploy/scripts/lib.sh` `app_env`). `DEPLOY_*` stay local. Production requires `JWT_SECRET`, `TREASURY_PUBKEY`, `TRUST_PROXY=1`; Solana is devnet-only (`validate-env.mjs` asks the RPC for its genesis hash).
- **Defaults differ between code and prod**: `VERDICT_ENFORCE` code `true` / prod compose `false` (shadow mode); `RIDE_MIN_SECONDS` 300 is a test value (prod 1800); `JWT_SECRET` unset in dev = random per boot; `TREASURY_PUBKEY` unset in dev = `backend/server/data/treasury.json`.
- **Secrets** (`JWT_SECRET`, `ADMIN_JWT_SECRET`, `EDITOR_JWT_SECRET`, `EDITOR_MCP_TOKEN`, `XAI_API_KEY` / `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY` / `ZAI_API_KEY` (read only by `infrastructure/llm/`, never in an event or a log), `WEBHOOK_SECRET`, `CRANK_SECRET`, `POSTGRES_PASSWORD`, `DEPLOY_ADMIN_PASSWORD`, `POSTHOG_KEY` (project token `phc_…` only – a personal `phx_…` is never stored), any `SOLANA_RPC` URL with an API key, `infra/deploy/secrets/*`): never in the chat, a commit, a log or an example file; `*.example` files hold dummies only. `POSTHOG_PROJECT_ID` (297915) is not a secret.
- **Test / tool env vars** (`TEST_DATABASE_URL`, `BASE`, `PORT`, `CHROME_PORT`, `CHROME`, `SHOTS`, `ADMIN_KEYPAIR`, `SMOKE_ADMIN_AUTH`, `DEPLOY_ENV_FILE`, …) are tabulated in the guide; Chrome debug ports are shared between sessions – set `PORT` / `CHROME_PORT` when another session may be running.
- **Browser state** that looks like config (`localStorage` `freightchain.*`: assist, level (the free level picked in the lobby), truck tuning, radio, admin, and `freightchain.anon`) lives in the player's browser – a stale value explains "only broken in my browser".
- Known drift is listed at the bottom of `docs/tech/configuration.md`; when you fix or add a key, update that page in the same change.

Security dependency overrides in `backend/server/package.json` pin undici 6.28.1, the legacy ethjs/number-to-bn bn.js dependencies to 4.12.5, and Prisma config's deepmerge-ts to 8.0.0. The last override intentionally crosses a major version: this project uses Prisma's plain config merge, and build/generation plus the PostgreSQL migration/integration suite check compatibility. A Solana-scoped Jayson 5 override removes the remaining production advisories; see `docs/insights/reviews/entity-editor-security.md` for compatibility checks.
Traffic verification: new starts stamp `trafficVersion=1` when `TRAFFIC_PROOF_REQUIRED=true` (default). The hashed `trafficProof` field is mandatory for those rides; body-level version claims cannot downgrade it. Protocol and browser tests: `docs/spec/anticheat.md`, `e2e.sh traffic`.

Convoy/campaign runtime repositories are PostgreSQL-backed (migration `20261113000000_durable_convoy_campaign`), with shared promo-cap serialization, social ownership uniqueness and rollback. The Convoy activation gift is a spendable 1h promo; legacy referral rewards remain separate. See `docs/spec/referral.md` for remaining provider and chain-settlement gaps.

Pool v6 schedule reads use explicit chain `opensAt` and `lastStartAt`; cadence uses `periodSecs`, independently of `saleSecs`. Cold-admin cancellation events can move an Active pool into refunding. The program remains local until a separately authorized fresh-program cutover.

The v6 schedule guard skips chain reads in transfer mode and propagates an RPC outage as unavailable in program mode: it cannot safely derive explicit opens/last-start fields from historical defaults. Road sealing reserves 80,000 CU for scanning the full SlotHashes window; local-validator coverage measures the late-slot case.

Pre-season social verification uses `TWITTERAPI_IO_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, and `TURNSTILE_SECRET_KEY` through EnvService. These are optional for boot; configured social checks require Turnstile (`action=preseason`, hostname from `APP_ORIGIN`). The Telegram request carries a signed Login Widget `proof`, never just an untrusted numeric ID. Provider reads run before the transaction; ownership binding is rechecked and persisted under the player lock. Tests replace only provider HTTP responses, not the adapters. Owner setup: configure the bot's Login Widget domain and channel membership access, X read API key, and Turnstile site/secret; never paste secrets into test fixtures.
