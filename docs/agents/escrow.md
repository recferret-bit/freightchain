# Money + escrowed pools – detail

Agent reference, moved verbatim out of `AGENTS.md` (which keeps only the map and the hard rules and is loaded into every agent session); an "In short" block, where there is one, is a summary. Read the file for a topic before changing it; keep it current like AGENTS.md ("Maps stay current").

## In short

- One road per competition: a ticket ride is driven on its pool's `Pool.rideSeed`, a pay-per-ride order on its tier's seed of the UTC day (`ride.DailySeed`); free rides draw their own.
- Money (legacy, `PAYMENT_MODE=transfer`): one global weekly round, a `Payment` row per paid entry, floored lamport shares – .
- **Escrowed pools** (paid tickets; plan / status `docs/paid-tickets-plan.md` / `docs/paid-tickets-status.md`; what is not done + open questions + todo: `docs/escrow-open-items.md` – update it when you close or find something): the money is in the Anchor program `programs/freightchain-pools` (each pool its own vault; a pool that misses `minTickets` by `prepDeadline` fails and anyone can refund). The server only MIRRORS pools (the chain wins) and credits tickets from program EVENTS (the confirm fast path, the program-log watcher, `POST /api/chain/webhook`; `(signature, eventIndex)` unique). Every wallet signs AND sends its own transaction (fee + Ticket rent; no gas sponsor, no `/submit`); the crank (`CRANK_SECRET`, `pool:crank`) sends only permissionless steps by the CHAIN clock and is the only key the server holds. Program mode is ticket-only (no pay-per-ride fallback). Lock order player → pool → tickets. Toolchain: `export PATH="$HOME/.cargo/bin:$HOME/.local/share/solana/install/active_release/bin:$HOME/.avm/bin:$PATH"`, `npm run program:build|test`; after a program change `program:idl` → `(cd server && node scripts/vendor-idl.mjs)` → regenerate `server/test/fixtures/chain/pool-program.json`. Deploy only the `solana-verify build` output (`npm run program:verify`, hash pinned in `verifiable-build.hash`). Never touch the global Solana CLI config or `~/.config/solana/id.json`; chain commands always with an explicit `--url devnet`; no deploy or pool creation without the user (it needs their Phantom).

## Detail

- **One road per competition** (`CreateRideHandler`): a ticket ride takes its pool's `Pool.rideSeed` (the server's, drawn once when the pool enters the mirror – `PoolRegistryService` / `pool:register` / `pool:seed` –, never updated: the upsert writes it only on insert; not on chain, not in the pool DTOs); a pay-per-ride order takes its tier's seed of the UTC day it was ORDERED (`DailySeedRepositoryPort.claim`: the day's first order stores its candidate with INSERT … ON CONFLICT DO NOTHING inside the create transaction, a racing first order waits on the `(tier, day)` key and reads the winner – concurrency-tested). Route, start hour, layout and holes follow from the seed, so a pool's (or a day's) riders drive the same ride. The seed is public once the first of them starts (the watch API); a second ticket drives the same road again. Free rides draw a seed each.
- Money: one global weekly round (UTC Mon→Mon); every paid entry (whatever the ride's outcome) is a `Payment` row; shares are floored integer lamports, remainder to fees; the grand prize shown is what has *accrued* – no draw/settlement/payout code yet. Demo wallets (`DEMO_WALLETS`) get paid shifts ÷`DEMO_SCALE` (`timeScale` on the ride; the speed bound is not scaled). This weekly round is now the LEGACY pay-per-ride path (kept as the `PAYMENT_MODE=transfer` fallback).
- **Solana Pay + reference keys.** A pay-per-ride order, a ticket order and a paid donation each get one reference (base58 of 32 random bytes, private key discarded) the first time a transaction is built for it. The reference is a read-only account on the memo instruction (`buy_ticket`'s account list is unchanged). Confirm still takes the desktop signature. Reconcile looks the payment up with `getSignaturesForAddress(reference)` instead of the wallet's last 25 signatures. A phone pays the same transaction through a public transaction request, no session: `GET/POST /api/solana-pay/{rides|orders|donations}/:id` (`POST` body `{ account }`). The lobby QR is `solana:` plus that URL, URL-encoded. CORS for `/api/solana-pay` is `*`; every other route stays on the origin allowlist. Errors stay problem+json and also carry `message` so a wallet can show them. Reopening the lobby looks up an unpaid ticket order by its reference. Reloading a watch page looks up a donation order this browser started. A memo the RPC leaves unparsed (the reference account is on it) is still read from the instruction bytes.
- **Escrowed pools (paid tickets – docs/paid-tickets-plan.md, status in docs/paid-tickets-status.md)**: a paid tier is sold as TICKETS into an on-chain pool (`programs/freightchain-pools`): the money sits in the pool's program-owned vault; if fewer than `minTickets` are sold by `prepDeadline` the pool fails and anyone can trigger the refunds; a live pool pays prizes (`pay_prize`, capped on chain, only after the pool's REVIEW window `payout_at`) and splits the rest to the seed / fee treasuries at close. **Program v3** (`programs/freightchain-pools` README "v3"; 21 instructions, 18 events, 32 errors; an in-place upgrade of `8No42h…`): (1) **road seed on chain** – `create_pool` / `open_next_pool` read the newest SlotHashes sysvar entry themselves and store `seed_commitment = SHA-256(pool_id LE u32 ‖ slot hash ‖ slot LE u64)` + `seed_slot` / `seed_slot_hash` (no caller passes a seed; `Pool.fromChain` derives `rideSeed` from it with `projectRoadSeed`, `domain/road/provable-seed.ts`; the game re-hashes it in the browser and shows ROAD SEALED ✓ in the cab – `client/js/seal.js`, `ui/cab-chain.js`, which also shows the pool's standings and the ride's pledges while driving); (2) **Attestation** `[b"attestation", pool, driver]` – `telemetry_root` (RFC 6962 Merkle root of the ride's batch hashes, `domain/telemetry/telemetry-merkle.ts`), `verified_km`, `status` 0 unverified / 1 verified / 2 flagged – written only by the admin or the payout key (`record_attestation`, Active pools): it is the SERVER's verdict put on chain, not a proof; `pay_prize` refuses a wallet without a VERIFIED one (`AttestationService.ensureAttestation`, floor km, never rounds a ride under 1 km up); (3) **pledges** `[b"pledge", ride_id (uuid, zero-padded to 32 B), sponsor]` – a spectator locks `lamports_per_km × target_km` (`create_pledge`, before the pool's play deadline); `settle_pledge` (permissionless, needs the driver's verified / flagged attestation) pays `max × min(km, target) / target` to the driver and closes the account (rest + rent → sponsor); `refund_pledge` (permissionless) gives everything back once the pool failed / was cancelled / closed / is past its grace and the driver has no decided attestation. Server: `POST /api/pledges` answers the unsigned `create_pledge` (row `pending`), the sponsor's wallet signs AND sends it, `POST /api/pledges/:id/confirm` reads that transaction's PledgeCreated (→ `active`); the payout job attests every pledged driver before `close_pool` (also on `no_winners`), then `SyncPledgesHandler` (after every payout pass) follows each open pledge's account history and sends settle / refund with the payout key (rows `settled` / `refunded`, never computed off chain; `abandoned` = never signed, 1 h). UI: the watch page's PLEDGE block on a ticket ride (`client/js/ui/watch-pledges.js`). Not built: any staking yield (v3's `record_yield` was removed before it went live – the always-0 `stakedLamports` / `yieldEarned` columns were dropped by migration `20261026000000`). **The payout job** (`PayPoolsCommand` → `PoolPayoutScheduler` every `PAYOUT_INTERVAL_MS`, CLI `pool:payout [--pool N]`, `PAYOUT_SECRET`, port `PoolPayoutChainPort`, AppModule only): for each active pool past `payout_at` (chain clock) and not on an admin's signed HOLD (`POST /api/admin/pools/:id/hold`, `Pool.hold`), it runs `PoolAttentionService.markPool`, waits while ANY completed ride of the pool is undecided (`waiting_review` – `RideQueryPort.poolUnreviewed`), plans the VERIFIED top 20 (always verified-only, whatever `VERDICT_ENFORCE` says) into `economy.PoolPayout`, records the winner's VERIFIED attestation (`AttestationService.ensureAttestation`), CLAIMS each prize there (planned → sent with its signature) before broadcasting, resolves a crash from the signature, attests every pledged driver, then closes the pool; no verified winner = `no_winners` for the admin; `payout-grace` is logged 3 days before the grace ends. Server-owned `Pool.payoutState` / `hold` change only through `savePayout` / `saveHold` (a chain sync never erases them). Public `GET /api/pools/:id/standings` = the winners list (provisional until planned, then paid per rank); `GET /api/pools` adds `finished` (the last settled pools). Server side: `Pool` = the MIRROR of the account (the chain wins; `PoolRegistryService.syncFromChain`), `RideTicket` per wallet per pool (+ `TicketGrant` audit trail, capped at the pool's `maxPerWallet`), `PromoCode` (free tickets of a tier, atomic last redemption), `TicketOrder` (one per purchase; `(signature, eventIndex)` unique = idempotency). `POST /api/rides` on a pooled tier spends one ticket and the ride is driven on the POOL's seed (`Pool.rideSeed`: since v3 projected from the pool's on-chain `seed_commitment` when the pool enters the mirror – a pre-v3 pool without one keeps a seed the server drew –, never updated, not in the pool DTOs; one pool = one road – route, start hour, layout, holes – for all its riders, the next pool a new one) (in `program` mode paid rides are ticket-only). Payments are credited from the program's EVENTS (`SettleChainSignatureCommand` → `TicketSettlementService`), reached three ways: the confirm fast path (the wallet signs AND sends its own transaction – it pays its network fee and the Ticket rent; there is no gas sponsor and no `/submit`), the program-log watcher (`infrastructure/scheduling/program-watcher.ts`, `WATCH_INTERVAL_MS`, AppModule only – the admin CLI boots ApplicationModule without timers) and `POST /api/chain/webhook` (`WEBHOOK_SECRET`; only signatures are read from the body). The server never holds the admin / treasury key. **Devnet phase** (`docs/escrow-open-items.md`, `docs/program-deploy.md`): `server/scripts/devnet.sh` – keys in the main checkout's `deploy/secrets/devnet/`, the local profile `server/.env.devnet` (the server / CLI with `ENV_FILE=.env.devnet`), `check-rpc` (QuickNode devnet), `db`, `server`, `cli`, `admin`, `payout` (`devnet-payout.mjs`), `rehearse` (the localnet scenario with `TARGET=devnet`). Admin CLI with keypair files (no Phantom): `server/scripts/pool-admin.mjs` (initialize / create-pool / set-config / sponsor / buy / pay-prize / record-attestation / create- / settle- / refund-pledge / fail-pool / expire-pool / close-pool / show, explicit `--url`, mainnet refused). Dev CLI: `pool:seed` (refused in production), `pool:register`, `pool:crank`, `pool:payout`, `promo:create|list|disable`, `tickets:grant`, `verdict:rejudge`, `retention:sweep`. **The pool crank** (`CRANK_SECRET`, fee money only, its own port `PoolCrankChainPort`): `CrankPoolsCommand` first opens each due series' pool (`seriesDue`, `open_next_pool` – the crank pays the new pool's rents), then reads every pool from chain (`Config.pool_count`), judges by the CHAIN clock (`domain/economy/pool-crank.ts` `nextCrankStep`) and sends `fail_pool` (missed goal), `expire_pool` (active, `payout_at` + 14 d, no prize paid), refunds in batches of 8 (tickets via `getProgramAccounts`), `close_pool` of a fully refunded pool – each signature settled at once; `PoolCrankScheduler` every `CRANK_INTERVAL_MS` (60 s; 0 = CLI only), AppModule only. It never closes a pool that paid prizes (the payout key closes it after paying). **Program mode is ticket-only**: a paid tier with no live pool is not on sale (`GET /api/tiers` `available: false`, the lobby's NO POOL card, `POST /api/rides` 409) – the legacy pay-per-ride stays for `PAYMENT_MODE=transfer`. A ticket is spent when its ride is ORDERED (`POST /api/rides`), only in a live pool before its play deadline – `TicketBalanceDto.ridable` / `rideBy` say so, the lobby shows "ride by" and lists unused tickets of a closed pool as expired, a late order is 409 `rides_closed`; an unused ticket of a live pool is not refunded (its money stays in that pot). A ticket is `refundable` as soon as its pool missed its goal (the refund transaction bundles `fail_pool`), not only once the pool is refunding. Program: `npm run program:build` (`anchor build --arch v0` – LiteSVM can't load SBPF v3) / `program:test`, with `export PATH="$HOME/.cargo/bin:$HOME/.local/share/solana/install/active_release/bin:$HOME/.avm/bin:$PATH"`; after changing the program: `program:idl` → `(cd server && node scripts/vendor-idl.mjs)` → regenerate `server/test/fixtures/chain/pool-program.json` (see `tests/export_fixtures.rs`). Never touch the global Solana CLI config or `~/.config/solana/id.json`; chain commands always with an explicit `--url devnet`. **Deploy only the `solana-verify build` output** (`npm run program:verify`; image pinned by `[workspace.metadata.cli] solana` in the program's `Cargo.toml`, hash pinned in `verifiable-build.hash` – a program change updates the pin with `UPDATE_PIN=1`); a local `anchor build` gives other bytes and never verifies.
