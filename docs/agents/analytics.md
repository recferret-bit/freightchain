## Detail

Capture ships on this checkout. The browser posts an allowlist to `POST /api/telemetry`; the server emits after the database commit. Production sends when the running image includes this code and `deploy/.env` has `POSTHOG_ENABLED=1` with a `phc_` token and `POSTHOG_DISABLED` unset. Local `server/.env` pins `POSTHOG_ENABLED=0`, so `npm run server:dev` does not send. The explainer is the full list: events, the eleven funnels with windows (9 = promo codes, 10 = the paid-consent clicks, 11 = the pitch deck), the five judge numbers, identity, the relay, the board recipe. Keep it in step with `server/src/domain/analytics/{client,server}-events.ts` and `application/services/analytics-events.ts` when they change. It is docs-only (not copied into `client/`).

- **Cloud EU, project 297915.** Capture is `POST {POSTHOG_HOST}/batch/`, host `https://eu.i.posthog.com`. The US ingest host accepts a token and the events never show up on the board. The Colosseum board is https://eu.posthog.com/project/297915/dashboard/1006663 (private, login wall, screenshot only, no public share). Loop health is a second blank dashboard and does not exist yet. Pick Blank, not a product template. Tiles stay at zero until someone adds them. Ingested events show in Activity, not on an empty board.
- **Two planes.** The browser posts an allowlist to `POST /api/telemetry` (`OptionalSessionGuard`, anonymous ok, max 10, response `{ enabled, accepted, dropped }`). The project token stays on the server. The relay forces `source: client` and drops every name in `SERVER_EVENTS`, so a client cannot mint `ride_completed` or `payment_confirmed`. When `enabled()` is false the relay returns `{ enabled: false, accepted: 0, dropped: 0 }` and the browser stops for that document. Server events are built only after the DB commit, inside `emitAnalytics`, and only when the port is on. `payment_confirmed` only when `settle()` returns `inserted` and `paidAt`. No player-row lock on the relay. No `posthog-js`, no second project, no nginx `/ingest/`. There is no client `.env`.
- **Identity.** Anon id `anon_<uuid v4>` in `localStorage` `freightchain.anon` via `store()` (version nibble 4, variant 8/9/a/b). Server events use the session wallet. `free_rides_granted`, `round_opened`, and `round_closed` use distinct id `freightchain`. `$create_alias` fires only on `session_restored` when `request_alias === true` (the string `"true"` does not alias). **Open bug — do not flip it:** the code sends `distinct_id` = the anon id and `properties.alias` = the wallet, which is what the approved plan says. PostHog's ingestion page says alias merges into `distinct_id` (that payload would fold the wallet into the anon); the capture API example says the opposite. The acquisition funnel stays unpublished until one real `session_restored` is checked in the UI.
- **Dedupe and volume.** UUID v5 of `https://freightchain.fun/analytics/` + `dedupe_key` (RFC 4122 URL namespace), computed in the adapter. Handlers pass `uuid: null`. No `$insert_id`, no `sent_at`, no `$groups`. No per-heartbeat events; `ride_progressed` only at 25/50/75. `payment_reconcile_missed` is stamped at 00:00:00.000Z of its UTC day (`utcDayStart`). `ride_resumed` (server: create returned an existing open ride) and `ride_unpaused` (client: pause menu) are different events; a unit test keeps the lists disjoint. Offline `play.html` emits no product events. `viewer.html` emits nothing. `web_vital` is the landing, the whitepaper, the pitch deck, and the lobby only. **Pitch deck** (`pitchdeck.<apex>`, `landing/src/pitchdeck/stats.js`): `pitchdeck_viewed` (once per load; `from` landing / whitepaper / homescreen / direct / other — `source` stays the client/server plane — `src` = the link's `?src=` tag), `pitchdeck_slide_viewed` (first view of each slide per load), `pitchdeck_slide_time` (visible ms, on change / leave), `pitchdeck_interaction` (first use of each toy), and `pitchdeck_link_clicked` on the landing pitch-deck band and the footer; sent anonymously (`configure({ credentials: 'omit' })`), `pitchdeck.<apex>` is in `CORS_ORIGINS` for it, its anon id is its own (per origin).
- **Crashes.** `client/js/crash.js` listens for `error` and `unhandledrejection` on the landing, the whitepaper, the pitch deck (`credentials: 'omit'`), the lobby, and `play.html` (a paid ride and the guest run). It does not hook `console`. Three reports per page, one per name plus top frame. `POST /api/client-error` (`OptionalSessionGuard`, anonymous ok). The handler (`ReportClientErrorHandler`) drops `Script error.`, `ResizeObserver`, `AbortError`, and extension-only stacks, scrubs query strings and long base58, and allows 10 per IP per minute and 2,000 per UTC day. Over the cap the response is still 200 `{ enabled, accepted: 0 }`. The adapter sends `$exception` with `$exception_list` (throw site last) on the same `/batch/`. The distinct id is the session wallet, else the anon id. A release is a 7–40 hex sha or it is omitted. Vite's hidden source maps are not uploaded by this path. `$exception` is not a `CLIENT_EVENTS` name and is not a tile on dashboard 1006663. Session replay stays off.
- **Page speed.** One Trends insight, not five, and not PostHog's `$web_vitals` page (`posthog-js` stays out). Event `web_vital`, aggregation Total count, breakdown the event properties `metric` then `rating`, bar chart of the whole date range, name **Page speed**. Do not pin it to dashboard 1006663. Each bar is a pair (`LCP / good`). `good` is fine, `needs-improvement` is slow, `poor` will be noticed; if `good` is taller, most visits are fine. A third breakdown `surface` names the page. The five names: **TTFB** Time to First Byte (HTML starts to arrive; poor means the wait is before anything can draw). **FCP** First Contentful Paint (first text or image). **LCP** Largest Contentful Paint (the hero, the whitepaper article, the lobby — what people feel as "the page is slow"). **INP** Interaction to Next Paint (a click or key; recorded only after one happens, sent on leave; an empty bar is normal). **CLS** Cumulative Layout Shift (not a time; `0` means nothing moved; raw `value` `100` is a score of `0.1`). Wording also in README "Product analytics" and `docs/analytics/index.html` → "Page speed".
- **Env.** Capture is opt-in. `POSTHOG_ENABLED` is the enum `1|true|0|false` (not a coerced boolean): only `1` or `true` may send, and unset / empty / `0` / `false` stays off even with a `phc_` token. `POSTHOG_KEY` empty = off. A non-`phc_` value logs once (`analytics disabled: POSTHOG_KEY is not a project token`) and does not refuse boot. `POSTHOG_DISABLED` of `1` or `true` is the kill switch and wins over the opt-in. `emitAnalytics` checks `AnalyticsPort.enabled()` (the decision from `EnvService`) and does not build the event when that is false; application code does not read `process.env`. `POSTHOG_PROJECT_ID` is notes only and is never sent. Real token only in the gitignored env files. Local development (`server/.env`, and root `docker-compose.yml`, which is Postgres only and must not set `POSTHOG_*`) pins `POSTHOG_ENABLED=0`. Production `deploy/.env` sets `POSTHOG_ENABLED=1`. The schema declares the keys. The tracked examples match the split (`server/.env.example` is `0`, `deploy/.env.example` is `1`, key blank). Prod compose passes `${POSTHOG_ENABLED:-}` and `${POSTHOG_DISABLED:-}` through; an empty value stays off, and a key missing from compose never reaches the container. A shell `POSTHOG_ENABLED=1` wins over `server/.env` for that process. CI stubs `fetch` to `https://posthog.test` with `phc_test` and `POSTHOG_ENABLED=1`.
- **Not this work.** Session replay and ride replay are verified play. Verdicts, escrow ticket buys, and live-stream events are not analytics events. `payment_confirmed` still fires only when memo `settle()` returns `inserted` and `paidAt`. A ticket ride emits `ride_ordered` (the ride, not the purchase). North star is server `ride_completed`, free and paid, split by `is_demo`, with no `round_id` filter. Lamports are the sum of `payment_confirmed.lamports` for the round, matching `GET /api/pool` `split.entries`, not `split.grand`. If PostHog and SQL disagree, quote SQL.
