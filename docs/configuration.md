# Configuration guide

Everything in Freight Chain that can be configured, where it lives, and what to change for what. The source of truth for server settings is
[`server/src/infrastructure/config/env.schema.ts`](../server/src/infrastructure/config/env.schema.ts) – this page explains it; if they disagree, the schema wins (and fix this page).

## The map

| What | File | Committed? | Used for |
|---|---|---|---|
| Server settings, local dev | `server/.env` (copy of `server/.env.example`) | no / example yes | `npm run server:dev`, Prisma, tests |
| Production settings | `deploy/.env` (copy of `deploy/.env.example`) | no / example yes | `npm run deploy`; uploaded to the server as `/srv/freightchain/.env` |
| Production secrets on disk | `deploy/secrets/` (`treasury.json` keypair, optional `program-deploy.json`) | **never** | generated by `npm run deploy:init`; never uploaded |
| Local database | `docker-compose.yml` (`FREIGHT_POSTGRES_*`) | yes | dev PostgreSQL on `127.0.0.1:15433` |
| Production stack | `deploy/docker-compose.prod.yml` | yes | which env keys reach the app container (see the trap below) |
| Game tunables | `client/js/config.js` (`CFG`) | yes | gameplay numbers: ride length, shake, traffic, climate… |
| Hosts / URLs | `client/js/hosts.js` | yes | derives API / game / site / admin URLs from the page's hostname |
| Verdict thresholds | `server/src/domain/verdict/verdict-rules.ts` (`RULES_VERSION`) | yes | verified-play rules |
| Ride rules mirrored from client | `server/src/domain/rides/ride-rules.ts` | yes | `MAX_SPEED`, `COMPLETE_DIST_K`, route ids – keep equal to the client |
| Solana program | `programs/freightchain-pools/Anchor.toml` | yes | program id, deploy wallet path |
| Landing build | `landing/vite.config.js` | yes | dev proxy to Nest, build output |
| nginx | `deploy/nginx/*.conf.template` | yes | the five hosts in production |
| Claude Code skills | `.claude/skills/*` | yes | read-only prod tooling + the test runner |
| Claude local settings | `.claude/settings.local.json`, `CLAUDE.local.md` | no | per-person |

`.gitignore` blocks `.env` and `.env.*` (except `.env.example`) and `deploy/secrets/`. **Never print or commit values from `deploy/.env`.**

## Two ways to run, two env files

- **Local**: `server/.env`. Only `DATABASE_URL` is required. Everything else has a dev default.
- **Production**: `deploy/.env` holds *both* deploy settings and the app's environment in one file.
  - Keys starting with `DEPLOY_` stay on your machine.
  - Everything else is uploaded as the server's `.env`.
  - `APP_DOMAIN`, `APP_ORIGIN`, `APP_PORT`, `COOKIE_DOMAIN`, `CORS_ORIGINS` are **derived** from `DEPLOY_DOMAIN` (`deploy/scripts/lib.sh` → `app_env`). Don't type them into `deploy/.env`.
  - Values starting with `CHANGE_ME` block the deploy until replaced. `npm run deploy:init` generates the secrets.
  - Before every deploy the production env is validated by the server's own schema in production mode (`deploy/scripts/validate-env.mjs`). It also refuses a non-devnet `SOLANA_RPC` (override for tests only: `ALLOW_NON_DEVNET=1`).

### ⚠ The compose pass-through trap

The app container only receives the keys **listed** in `deploy/docker-compose.prod.yml`. Putting a key in `deploy/.env` uploads it to the server, but if the compose file doesn't list it, the app never sees it and silently uses the default.

Every schema key except `NODE_ENV`, `PORT`, `DATABASE_URL`, `CLIENT_DIR`, `LANDING_DIR` (fixed by the image / compose) is forwarded. Keep it that way.

A new setting therefore touches **four** places: `env.schema.ts`, `server/.env.example`, `deploy/.env.example`, `docker-compose.prod.yml` (+ `deploy/scripts/init-env.mjs` if it is a generated secret).

## Server settings (`env.schema.ts`)

**Req** = required where noted. "prod" = `NODE_ENV=production`, which switches on the strict checks.

### Core

| Key | Default | Notes |
|---|---|---|
| `NODE_ENV` | `development` | `production` enforces `JWT_SECRET`, `TREASURY_PUBKEY`, `TRUST_PROXY` |
| `PORT` | `3000` | Prod container always uses 3000; the host port is `DEPLOY_APP_PORT` |
| `DATABASE_URL` | – (**required**) | Prod: built by compose from `POSTGRES_*` |
| `JWT_SECRET` | random per boot in dev | ≥ 32 chars, **required in prod**. Changing it signs everyone out |
| `SESSION_TTL_DAYS` | `7` | Rider session cookie lifetime |
| `APP_DOMAIN` / `APP_ORIGIN` | `localhost:3000` / `http://localhost:3000` | Shown in the wallet's sign-in message – must be the page the rider signs in on (derived in prod) |
| `CLIENT_DIR` / `LANDING_DIR` | `../client` / `../landing/dist` | Static roots. No landing build = `/` serves the placeholder `client/index.html` |
| `COOKIE_DOMAIN` | unset (host-only cookie) | Split hosts only: the apex, so all subdomains share the session. Bare host, no scheme/port |
| `CORS_ORIGINS` | empty (CORS off) | Split hosts only: comma-separated origins allowed to call the API with the cookie |
| `TRUST_PROXY` | – (**required in prod**) | Reverse-proxy hops. Production nginx = `1` (the deploy check insists). Wrong value = per-IP rate limits wrong |
| `THROTTLE_LIMIT` / `THROTTLE_AUTH_LIMIT` | `600` / `30` | Requests per minute per wallet-or-IP; the second applies to `/api/auth/*` |

### Game rules & economy

| Key | Default | Notes |
|---|---|---|
| `FREE_RIDE_SECONDS` | `180` | Free-ride length. Test/demo override |
| `HB_MIN_INTERVAL_MS` | `1000` | Minimum spacing of ride heartbeats |
| `DEMO_WALLETS` | empty | Comma-separated wallets (or `*`) whose **paid** rides run `DEMO_SCALE`× shorter – for demo videos |
| `DEMO_SCALE` | `60` | |
| `INITIAL_SEED_SOL` | `0` | SOL the very first prize round starts with |
| `VERDICT_ENFORCE` | code `true`, **prod compose `false`** | `false` = shadow mode: rides are judged and shown but boards ignore the verdict |
| `TELEMETRY_RETENTION_DAYS` | `90` | Recordings swept after this; flagged ones kept until reviewed; `0` = forever |

### Solana & payments

| Key | Default | Notes |
|---|---|---|
| `TREASURY_PUBKEY` | – (**required in prod**) | PUBLIC address receiving fees. Dev: falls back to `server/data/treasury.json` from `npm run treasury:init` |
| `SOLANA_RPC` | devnet public | **Devnet only** – deploy refuses others. A dedicated URL contains an API key → only in `deploy/.env` |
| `SOLANA_WS` | derived from `SOLANA_RPC` | Websocket of the same provider |
| `SOLANA_RPC_FALLBACKS` | empty | Comma-separated read-only fallbacks |
| `SOLANA_COMMITMENT` | `confirmed` | or `finalized` |
| `SOL_USD` | live price | Pin the price (tests/offline). Empty/0 = Coinbase then CoinGecko, cached 60 s |
| `PAYMENT_MODE` | `program` if `TICKET_PROGRAM_ID` set, else `transfer` | `program` = escrow pools via the Anchor program; `transfer` = plain transfers to the treasury |
| `TICKET_PROGRAM_ID` | unset | Deployed pool program id. Required when `PAYMENT_MODE=program` |
| `FEE_TREASURY` / `SEED_TREASURY` | unset | PUBLIC keys: defaults for new pools |
| `WATCH_INTERVAL_MS` | `15000` | Program-log watcher poll; `0` = off |
| `ORDER_TTL_MINUTES` | `60` | How long a paid order stays payable |
| `ONCHAIN_SESSION_TTL_HOURS` | `24` | max 168 |
| `WEBHOOK_SECRET` | unset | **Secret**, ≥ 16 chars. Unset = `POST /api/chain/webhook` answers 404 |
| `CRANK_SECRET` | unset | **Secret** base58 keypair paying fees for permissionless cranks (fail_pool, refund) |
| `FEE_PAYER_SECRET` | unset | **Secret** base58 keypair of the gas sponsor – fee money only. Unset = buyers pay their own fee |
| `FEE_PAYER_MIN_SOL` | `0.05` | Sponsor stops below this balance |
| `SPONSOR_PER_WALLET_PER_DAY` | `20` | |
| `PRIORITY_FEE_PERCENTILE` / `_MIN_MICROLAMPORTS` / `_MAX_MICROLAMPORTS` | `75` / `0` / `50000` | Min ≤ max. Use min `1000` on mainnet |

### Admin

| Key | Default | Notes |
|---|---|---|
| `ADMIN_WALLETS` | empty | Comma-separated base58 wallets allowed on the admin page. **Empty = no admin surface at all** (every admin route 404s) |
| `ADMIN_JWT_SECRET` | derived from `JWT_SECRET` | ≥ 32 chars. Rotating it signs all admins out. |
| `ADMIN_SESSION_TTL_MINUTES` | `120` | max 1440; no silent renewal. |

The admin API additionally requires: host = `admin.<apex>` (nginx basic auth, `DEPLOY_ADMIN_USER` / `DEPLOY_ADMIN_PASSWORD` ≥ 16 chars), a wallet sign-in, and a wallet signature for every change.

### Product analytics (read on `plan/posthog-integration`; stripped on `main`)

The capture code is not on `main`. `env.schema.ts` here does not declare these keys, so Zod strips them and boot is unchanged. They are still listed in `server/.env.example`, `deploy/.env.example`, and `deploy/docker-compose.prod.yml` `app.environment`, because a key missing from compose never reaches the container once the branch is merged. Full behaviour: [`docs/analytics/index.html`](analytics/index.html).

| Key | Default | Notes |
|---|---|---|
| `POSTHOG_KEY` | unset | Project token `phc_…`. Empty = capture off. A `phx_…` or any other non-token is logged once and ignored, and does not stop the API. **Never commit or print it.** Tracked examples stay empty. The real value is only in gitignored `server/.env` and `deploy/.env`. |
| `POSTHOG_HOST` | `https://eu.i.posthog.com` | Ingest. Capture posts to `{host}/batch/`. Project 297915 is EU Cloud. The US ingest host accepts the token and the events never appear on the board. |
| `POSTHOG_PROJECT_ID` | `297915` | Notes only. Not a secret. Not sent on capture. |
| `POSTHOG_ENABLED` | off when unset | Global opt-in. Only `1` or `true` may send. Unset, empty, `0`, or `false` stays off even when `POSTHOG_KEY` is a project token. An enum, not a coerced boolean. Local `server/.env` and `server/.env.example` set `0`. Production `deploy/.env` and `deploy/.env.example` set `1`. The local compose file does not run the API and does not set this. |
| `POSTHOG_DISABLED` | unset | Kill switch. `1` or `true` forces capture off even when `POSTHOG_ENABLED` is on. `0`, `false`, or empty does not turn capture on. An enum, not a coerced boolean (`"false"` must not stick the switch on). |

## Deploy-only keys (`deploy/.env`, never reach the app)

`DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PATH` (must be under `/srv`), `DEPLOY_DOMAIN` (bare apex – `ride.`, `api.`, `storybook.`, `admin.` are added), `DEPLOY_LETSENCRYPT_EMAIL`, `DEPLOY_APP_PORT`, `DEPLOY_KEEP_RELEASES` (3), `DEPLOY_KEEP_BACKUPS` (7), `DEPLOY_ADMIN_USER`, `DEPLOY_ADMIN_PASSWORD`.
Also read by the compose file on the server: `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` (hex only), `APP_PORT` (derived), `RELEASE` (set by the deploy).

DNS: five A records (apex, `ride`, `api`, `storybook`, `admin`) → `DEPLOY_HOST`. The session cookie is `Secure`, so https only.

Typical local setup:
```sh
cp server/.env.example server/.env   # edit nothing for a first run
npm run db:up && npm run db:migrate
npm run treasury:init                # dev treasury key → server/data/treasury.json
npm run server:dev                   # :3000 – site, game and API on one origin
```

## Client settings

- **`client/js/config.js` (`CFG`)** – every gameplay constant, with comments. Deliberate values not to touch without asking: `SHAKE_START 0.5`, `SHAKE_MOVING 0.1`, `SHAKE_RPM 0.35`, `START_ENGINE_OFF true`.
  `RIDE_MIN_SECONDS` is **300 (a test value); production = 1800**. Tuning requests are relative to the current value.
- **Hosts** – never hard-code `/api/…` or `/play.html`; use `API_BASE` / `GAME_BASE` / `SITE_BASE` / `STORYBOOK_BASE` / `ADMIN_BASE` from `client/js/hosts.js`. On localhost, an IP or `file://` they are `''` (one origin).
- **Browser `localStorage` keys** (per player, not config you ship): `freightchain.wallet.v1` (mock wallet), `freightchain.route` (last route), `freightchain.truck` (F2 handling tuning), `freightchain.time` / `freightchain.daycycle` (day-night clock), `freightchain.radio`, `freightchain.admin`. The analytics branch also writes `freightchain.anon` (`anon_<uuid v4>`).
  A stale value is the first suspect for "works in a fresh browser only" – clear them.
- **In-game F2 panel** – live sliders for truck handling and the time of day.
- Server rules that mirror the client (`MAX_SPEED`, `COMPLETE_DIST_K`, route ids) live in `server/src/domain/rides/ride-rules.ts` – change both together.

## Other things you can configure

- **Landing** (`landing/`): dev proxy in `vite.config.js`; `LANDING_DIR` on the server; size budget enforced by `landing/test`.
- **App icon**: generated – edit `design/icons/build-app-icons.mjs` and rerun, never the PNGs.
- **nginx / certificates**: `deploy/nginx/*.conf.template`, applied by `npm run deploy:setup` (a new host = new template + `setup.sh` + smoke check + `hosts.js` prefix).
- **Anchor program**: `programs/freightchain-pools/Anchor.toml` (program id, `wallet` → `deploy/secrets/program-deploy.json`, gitignored). Building: `npm run program:build`, `program:test`, `program:idl`.
- **Logging**: JSON lines in production, ring buffer of 5000 in memory for the admin page; read with `npm run ops -- logs`.
- **Scheduled jobs** (no env): free-ride refill 00:00 UTC, telemetry sweep 00:30 UTC.

## Checklist: first production deploy

1. `npm run deploy:init` → edit `deploy/.env` (domain, e-mail, host; `ADMIN_WALLETS`; dedicated devnet `SOLANA_RPC`).
2. Five DNS A records → `DEPLOY_HOST`.
3. `npm run deploy -- --dry-run` and read the plan.
4. Only then `npm run deploy` (needs the explicit go-ahead; see AGENTS.md "Deploying to production").

## Known drift

- `POSTHOG_*` in the gitignored env files is intentional and the two files differ. Local `server/.env` pins `POSTHOG_ENABLED=0` (the local compose file is Postgres only and must not turn capture on). Production `deploy/.env` sets `POSTHOG_ENABLED=1`, EU host, project 297915, token not tracked. On `main` the schema strips the keys, so the live site ignores them until `plan/posthog-integration` is the image production runs. Do not point the host at `us.i.posthog.com`. Do not delete the keys to “clean up” — the analytics branch reads them. `POSTHOG_DISABLED=1` still wins after that deploy.
- `deploy/.env.example` omits `FEE_PAYER_*` / `CRANK_SECRET` / `POSTHOG_KEY` real values on purpose (dummies and an empty token) and does not list `COOKIE_DOMAIN` / `CORS_ORIGINS` / `APP_*` (derived).
