Where a fact is born

The browser proposes, the server disposes

Capture is on this checkout as of 8 Oct 2026. Verified-play verdicts, escrow ticket buys, and live-stream chat are still not events. payment_confirmed is the memo-transfer confirm and reconcile. A ticket ride emits ride_ordered, which is the ride, not the purchase.

Server plane

quotes money

Distinct id is the session wallet. source is server. Nine P0 events cover sign-in, order, payment, start, progress, complete, abandon, fail. Thirteen more cover resume, expiry, conflicts, free-ride grants, achievements and their NFT mints, and round open/close.

Browser plane

explains the drop

Distinct id starts as anon_<uuid v4> in localStorage key freightchain.anon. Nineteen P0 events cover the landing, the whitepaper, the wallet prompt, the lobby, and the ride page. P1 and P2 are polish. They never decide a finish.

What a judge is allowed to hear

Five numbers, plus the lamports

Date range for the fair: 8 Oct 2026 through 12 Oct 2026, UTC. Every one of these filters source = server. is_demo is a property on the event, so a demo ride stays demo even if the person update was missed. Split real and demo. Do not add the two tiles into one sentence.

Completed shifts

North star. Count of server ride_completed, free and paid. No round_id filter — a free finish has no round, and filtering it away hides the only finish a playtester can reach before Sunday.

Wallets

Unique users on player_signed_in. One tile is_demo=false, one tile is_demo=true titled DEMO WALLET (×60 clock).

Lamports in

Sum of payment_confirmed.lamports for the open round_id. That sum is GET /api/pool → split.entries. It is not the entries count, and it is not split.grand.

Person-scoped funnels

Ten funnels, each with a window

A drop means that person did not fire the next event inside the window. That is sometimes a product bug and sometimes a judge who only looked at the pool. Click-together: Funnels → step → property filter → the window written here → breakdown one of is_demo, is_free, tier_id, stage, fail_code. Leave “exclude events between steps” off except where an exclusion is written. Ordered steps are already the order. PostHog does not OR a step, so free and paid are two funnels, and session restore is two funnels.

unpublished
  1. 1landing_viewed
  2. 2wallet_connect_clicked
  3. 3player_signed_in · source=server
  4. 4lobby_viewed
window 1 houralso a 24 hour copy

1→2 the page did not convince, or the button was off screen. 2→3 the wallet was missing, the prompt was rejected, the nonce failed, or the signature was bad — read sign_in_failed.stage. 3→4 the redirect to the lobby failed or the tab closed. Step 2 and step 3 join only because $create_alias merges the anonymous id into the wallet. Until one real session_restored has been checked in the PostHog UI, this funnel under-counts. Leave it unpublished and quote sign-ins from player_signed_in alone. A 7 day window is wrong: yesterday’s landing would convert into today’s click.

2a · Activation, free

7 days
  1. 1lobby_tab_viewed · tab=new
  2. 2ride_buy_clicked · is_free=true
  3. 3ride_ordered · is_free=true
  4. 4ride_started

The tier is a property of ride_buy_clicked. There is no separate tier click. A free ride is the one-minute free run (60 seconds and 420 m, ending by itself), so one sitting fits. A 3 minute window is enough for a demo; the 7 day window is so free and paid share one clock.

2b · Activation, paid

7 days
  1. 1lobby_tab_viewed · tab=new
  2. 2ride_buy_clicked · is_free=false
  3. 3ride_ordered · is_free=false
  4. 4payment_confirmed
  5. 5ride_started
  6. 6ride_completed

Quote TTL is 10 minutes, but reconcile can land on a later visit, and a real 1 h / 4 h / 8 h shift is longer than a sitting. Demo wallets finish the paid drive in about a minute (DEMO_SCALE 60). Everyone else cannot finish an 8 hour tier before the deadline. Say that in the caption. The video uses the demo board and says “demo clock ×60”.

Drops on activation: buy → order is a 409 (a ride is already running), a 503 on price or treasury, or ride_resumed because they already held the order. Order → payment is a wallet reject, a wrong amount, a memo mismatch, an RPC that has not shown the transaction, or a give-up. Payment → start means they paid and did not press START RIDE. Start → complete is abandon, fail, or still on the road. The main funnel does not exclude fails. An “honest finish” copy may exclude ride_failed with fail_code=implausible_progress.

3 · Payment reliability

30 min
  1. 1ride_buy_clicked · is_free=false
  2. 2payment_submitted
  3. 3payment_confirmed

In-session path: quote TTL 10 minutes, poll budget 90 seconds, wallet prompts run long. 4 · Free vs paid

same window

Funnels 2a and 2b are the comparison. A combined funnel with breakdown is_free on ride_started → ride_completed is the one tile that puts them side by side. Free completion is reachable in one sitting. Paid non-demo completion is not, except the demo wallet.

5 · Real vs demo

a filter, not a shape

Every funnel above gets is_demo=false for playtesters and is_demo=true for the demo clock. The submission video uses the demo board. An unfiltered funnel mixes a one-minute demo finish with an eight-hour shift.

Browser events · 42 names, allowlisted properties

What the player did before the server knew

The relay stamps source=client and, when the cookie verifies, the session wallet. Properties are strings of at most 200 characters, or an integer, a boolean, or null. A float drops that event, not the whole batch. At most 20 keys. Anything not in the allowlist is removed. These names are hard-deleted even if someone allowlists them later: signature, transaction, seed, nonce, message, token, cookie, authorization, detail, secret, anon_id.

Keys

What turns capture on

KeyMeaning
POSTHOG_KEYProject token, phc_…. Empty turns capture off. A personal phx_… key, or any other string, logs once (analytics disabled: POSTHOG_KEY is not a project token) and is treated as unset. It does not refuse boot. The real token lives only in gitignored server/.env and deploy/.env. Tracked examples keep it empty.
POSTHOG_HOSThttps://eu.i.posthog.com. Capture posts to {host}/batch/. The US host is the wrong continent for this project.
POSTHOG_PROJECT_ID297915. Notes for humans. Capture does not send it.
POSTHOG_ENABLEDGlobal opt-in. Only 1 or true may send. Unset, empty, 0, or false stays off even when the key is a project token. An enum, not a coerced boolean. Local server/.env and server/.env.example set 0. Production deploy/.env and deploy/.env.example set 1. The local compose file does not set it.
POSTHOG_DISABLEDKill switch. 1 or true forces capture off even when POSTHOG_ENABLED is on. 0, false, or empty does not turn capture on. An enum, not a coerced boolean, so the string false does not stick the switch on.

The schema declares these keys. Both example files and deploy/docker-compose.prod.yml list them: a key present in deploy/.env but missing from compose never reaches the container. A shell POSTHOG_ENABLED=1 wins over the local 0 for that process. POSTHOG_DISABLED=1 still wins.

What you can count on

  • A finish is a server rowride_completed exists only after the ride saved as shift complete. The browser cannot mint it.
  • A payment is an inserted rowpayment_confirmed fires only when settle() inserted the payment. A second confirm and a race loser are silent.

  • A bad key does not take the API downEmpty, phx_, POSTHOG_ENABLED left unset, or POSTHOG_DISABLED=1 disables capture and the process still listens.
