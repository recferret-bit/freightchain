## 0. The idea (what the judges see)

**Every prize pool is its own on-chain instance – an assurance contract for skill prizes.** A pool (one per ride tier per week, or per event) is a program account that states its rules in public and never changes them: ticket price, **minimum tickets to play**, **preparation period**, maximum per wallet, prize / seed / fee split, and the **treasury addresses** the seed and the fees go to. Players buy tickets into the pool's vault – a program-owned account; **the operator never holds entry fees**. If the minimum is not reached before the preparation deadline, the pool fails and **anyone can trigger the refunds** – every buyer gets every lamport back, no permission needed. If it is reached, the pool goes live, the rides happen, and the prizes are paid from the vault by the admin's signed instruction, each payout an on-chain event; seed and fees leave only at close, to the addresses the pool declared on day one. Sponsors can top up a live pool. Kickstarter for prize pools: commit-to-play, trustless refund, transparent split, no custody.

Server side the game stays "verified play": the server keeps the clock and the speed bound, ranks the finished rides of the pool, and the admin signs the payouts in Phantom. The server **observes** the chain (program-log watcher + QuickNode webhook) – it credits tickets from events, it never moves money.

**Accounts**
- `Config` `[b"config"]`: `authority`, `platform_treasury`, `platform_fee_bps` (part of the fee share; 0 for the hackathon), `pool_count: u32`, `paused`, `bump`.
- `Pool` `[b"pool", pool_id u32 LE]`: `pool_id`, `authority` (the pool's admin – today = Config.authority; **the field exists so pools can be hosted by others later**), `tier: u8`, `price_lamports: u64`, `min_tickets: u32`, `max_tickets: u32` (0 = ∞), `max_per_wallet: u16`, `prep_deadline: i64`, `play_deadline: i64`, `prize_bps / seed_bps / fee_bps: u16` (sum 10 000), `fee_treasury: Pubkey`, `seed_treasury: Pubkey`, `status: u8` (Open 0 · Active 1 · Refunding 2 · Settled 3 · Cancelled 4), `tickets_sold: u32`, `buyers: u32`, `sponsored: u64`, `prizes_paid: u64`, `refunded: u64`, `created_at`, `bump`, `vault_bump`. Immutable after creation except `status` and the counters.
- `vault` `[b"vault", pool_id]`: zero-data system account owned by the program's seeds – the escrow. **Rent rule (§2.9)**: `create_pool` funds it with the rent-exempt minimum from the authority; every outbound transfer must leave it `≥ rent_min` or bring it to **exactly 0** (the final sweep in `close_pool` / after the last refund) – the runtime rejects anything in between.
- `Ticket` `[b"ticket", pool, buyer]`: `buyer`, `rent_payer: Pubkey`, `pool_id`, `qty: u16`, `lamports: u64`, `refunded: bool`, `bump`. Rent (≈0.0015 SOL) is paid by the **fee payer** of the buy transaction (the sponsor when gasless, else the buyer) and recorded in `rent_payer`; `refund` returns the **ticket price to `buyer`** and the **rent to `rent_payer`** (so a sponsor is never drained by buyers of a failed pool), as does `close_ticket`. A buyer's net cost is the ticket price, nothing else.
- `Session` `[b"session", wallet, session_key]` (phase 2, §2.10): `wallet`, `session_key`, `expires_at`, `max_lamports` (spend allowance), `spent`, `bump`. `Balance` `[b"balance", wallet]`: the wallet's on-chain deposit that session purchases spend from.

**Instructions**
- `initialize(platform_treasury, platform_fee_bps)` – once; signer becomes `authority`.
- `create_pool(params)` – `authority`; `prep_deadline > now`, `play_deadline ≥ prep_deadline`, bps sum 10 000, `min_tickets ≥ 1`, `price > 0`. Emits `PoolCreated`.
- `buy_ticket(pool_id, qty: u16, order_id: [u8;16])` – signer = buyer; requires `status ∈ {Open, Active}`, `now < play_deadline`, `tickets_sold + qty ≤ max_tickets` (if set), `ticket.qty + qty ≤ max_per_wallet`; system transfer `price × qty` → vault; init-or-update `Ticket`; counters; **if `Open` and `tickets_sold ≥ min_tickets` → `Active` + `PoolActivated`**. Emits `TicketBought { pool_id, buyer, qty, lamports, order_id, tickets_sold, activated }`. Errors `Paused`, `PoolNotOpen`, `SoldOut`, `WalletCap`, `TooLate`.
- `sponsor(pool_id, lamports)` – anyone, `Open | Active`: transfer → vault, `sponsored += lamports`. Emits `Sponsored`. (One instruction, big story: brands top up a pool.)
- `fail_pool(pool_id)` – **permissionless crank**: `status == Open && now ≥ prep_deadline && tickets_sold < min_tickets` → `Refunding`. Emits `PoolFailed`. Also `cancel_pool` – authority, `Open` only → `Refunding` (`PoolCancelled`).
- `refund(pool_id, buyer)` – **permissionless** when `Refunding`: vault → buyer `ticket.lamports` (PDA signer), `refunded += …`, close `Ticket` (rent → `rent_payer`). Emits `Refunded`. Several `refund` instructions fit one transaction (the crank batches 8 per tx under the 1232-byte limit); each is idempotent (`refunded` flag → `AlreadyRefunded`), so a dropped or half-landed batch is simply re-sent.
- `close_ticket(pool_id, buyer)` – permissionless when `Settled`: closes the Ticket, rent → `rent_payer`. Sponsors' refunds: `refund_sponsor` is **not** built this week – sponsorship of a pool that then fails stays in the vault for the authority's `sweep` (documented); the lobby only offers sponsorship on **active** pools.
- `pay_prize(pool_id, to, lamports, rank: u8)` – `authority`, `Active`, `now ≥ play_deadline`; `prizes_paid + lamports ≤ prize_share` where `prize_share = (tickets_lamports + sponsored) × prize_bps / 10 000` (sponsorship goes 100 % to prizes? → no: it is split like entries, simpler and stated; **decision in §8**). Emits `PrizePaid { pool_id, to, lamports, rank }`.
- `close_pool(pool_id)` – `authority`, `Active`, `now ≥ play_deadline`: `seed_share → seed_treasury`, `fee_share → fee_treasury` (minus `platform_fee` → `platform_treasury`), `prize_share − prizes_paid` stays in the vault as unclaimed → it also goes to `seed_treasury` (so a pool always ends empty), `Settled`. Emits `PoolClosed { prize_paid, seed, fee, unclaimed }`.
- `set_config(paused?, platform_treasury?, platform_fee_bps?)` – authority.
- **Rent checks on the money paths**: `create_pool` requires `fee_treasury`, `seed_treasury` (and `platform_treasury`) to be **rent-exempt already** (`lamports ≥ rent_min`) – a transfer into an empty account below the minimum fails on mainnet; `pay_prize` requires `lamports ≥ rent_min` or the receiver already funded (always true for a buyer); `close_pool` ends with the vault at exactly 0.
- **Phase 2 (only if W1 is green Thursday night, else after the hackathon)** – session keys + deposit (§2.10): `open_session(session_key, ttl_s, max_lamports)` (wallet signs once; `ttl ≤ 7 d`), `close_session` (wallet, or anyone after expiry → rent back to the wallet), `deposit(lamports)` (wallet → `Balance`), `withdraw(lamports)` (wallet only), `buy_ticket_with_session(pool_id, qty, order_id)` (signer = the **session key**; pays from `Balance`; `spent + cost ≤ max_lamports`, not expired; emits the same `TicketBought` with `via_session = true`). Refunds go to the wallet whoever cranks them, so no session variant is needed.

### 2.10 Conversion – gasless transactions and session keys

Today a purchase costs the buyer a wallet popup **and** a network fee **and** SOL to pay that fee (on mainnet including the priority fee). Two layers, by payoff:

**Layer 1 – gas sponsorship (this week; W3 + W4 + W5).** The server already builds every transaction; it now sets `feePayer` to the sponsor key (`FEE_PAYER_SECRET`), keeps the exact message bytes with the order, and the wallet only **signs** (`signTransaction`), it does not send. `POST …/submit` verifies the returned transaction's message equals what was built (so nobody can make the sponsor pay for an arbitrary transaction – the fee-payer drain), checks the user's signature is present and valid, adds the sponsor's, sends with the re-send loop, records a `SponsoredTx`. Guard rails: per-wallet daily cap, the sponsor key holds fee money only (log alarm below `FEE_PAYER_MIN_SOL`; `deploy/README.md` says how to top it up), refunds are always sponsored (a refund must never cost the victim), buys are sponsored while the balance lasts, with an automatic client fallback to self-paid. Q8 holds: the sponsor cannot move anyone's funds – the user's own signature still authorises the transfer into the vault. Cost on mainnet ≈ 0.00001–0.0005 SOL per sponsored tx; noise against a $5 ticket, and **the** difference for a first-time buyer with 0 SOL. Alternatives considered: Kora / Octane (a separate relayer to run for the same result), Helius sponsored transactions (one provider).

**Layer 2 – session keys + on-chain balance (phase 2: this week only if the program is green Thursday night; otherwise the first post-hackathon milestone – §2.6 has the instructions, the server/client seams exist).** A SOL transfer needs the owner's signature, so a session key alone cannot buy. The pattern: the player makes **one** approval that opens a `Session` (a browser-held ephemeral key with a TTL and a spend allowance) and funds a `Balance` deposit; from then on every ticket is `buy_ticket_with_session`, signed in the page by the session key and sponsored by the server – **no popup, no fee, instant**. Sessions are scoped to buying tickets and nothing else, capped by `max_lamports`, expire (≤ 7 days), are revocable by the wallet; the deposit is withdrawable by the wallet only; the server never sees the session secret (it co-signs fees only). This is what makes "buy another ticket" one click, and the foundation for in-ride on-chain actions later (checkpoint attestations, challenge responses). Prior art: MagicBlock / Gum session keys; ours is five instructions in the same program, so the IDL and the watcher already cover it.

**Conversion UX (W5)**: BUY shows "network fee: sponsored"; a wallet with 0 SOL beyond the ticket price can buy; the second ticket with a session open is one click; every error names the fix (expired → rebuilt automatically; sold out; wallet cap; pool not open; sponsor empty → "pay the network fee yourself (≈ 0.0001 SOL)").
