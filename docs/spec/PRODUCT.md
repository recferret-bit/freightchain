### Weekly granted ticket and the prize board

**Shipped, with a draft contest.** 4h and 8h grants default off (`weekly_ticket_4h_enabled` and `weekly_ticket_8h_enabled` are 0).

### Verified play

**Shipped, production in shadow mode.** [`docs/spec/anticheat.md`](anticheat.md).

Drivers generate holes with the seeded local rules that the server judges. They do not request the public watch road endpoint, which refuses running and training rides. Eligible replays still fetch the server's road plan.

10 Hz samples, hash-chained batches, rules v7, traffic-frame proof required for new starts. The server rebuilds the road and the holes. Verdicts are `verified`, `flagged`, `rejected`. `VERDICT_ENFORCE=false` is the production default: judged and shown, boards and badges ignore a reject. The code default for tests is `true`. Machine-rejected paid rides stay under review until an admin decides. The live replay stays 10 Hz and rules v7 (decision 69, 24.10.2026). `TELEMETRY_V21` defaults to `off` and also accepts `shadow` and `enforce`. `shadow` issues a per-ride session key on start and checks an HMAC when a batch says `protocol: 2`. The v1 hash chain still accepts a batch with no protocol. `enforce` requires the named deflate streams `inp`, `clk`, `chk`, `mg`, and `env`, checks `HMAC-SHA256(sessionKey, rideId ‖ seq ‖ startTick ‖ endTick ‖ sha256(inp) ‖ sha256(chk))` before inflate, steps that input at `dt = 1/30`, and returns the re-derivable traffic and hole salts on start. A bad MAC is `400 batch-mac-invalid`. Enforce compares the client's `worldDigest32` with `worldDigest32` of the holes, junctions, and traffic spawned within ±300 m. A mismatch that lasts at least 10 seconds after three points in a row rejects; a shorter mismatch flags. `pauseVerdict` and `slowMotionVerdict`: mode `off` adds no reasons; `shadow` flags; `enforce` rejects. Humanness features F1–F10 score 0–100. The five physical-impossibility cases reject in that classifier; a borderline score or `isTrusted=false` is `flagged_for_review`. The top 20 verified rides by distance, while that pool's validation window is still open, are compared. A similar pair raises a `trace-cluster` alert and those rides are flagged for admin review. A copied trace of 50 or more intervals rejects the ride. Raw `inp` older than 90 days is eligible for deletion only after that pool's payout is finalized. `trustScore` starts at 60 and moves on a verified ride, a rejected ride, and a first social bind. Signing in does not award trust or write the existing player row. It does not store a browser fingerprint. Convoy M1/M2 and airdrop TEN4 ledger credits wait 48 hours and release only when both wallets are still at least 50 with no rejected rides. A player write whose terms or privacy version is missing or older is `403 terms_acceptance_required`. The key is not on GET or heartbeat. It is stored on the ride row in the clear. Heartbeats count pauses. In `shadow`, a fourth pause, more than five minutes paused, or a sustained game/wall ratio below 0.9 adds a flag (`pause-limit`, `pause-time`, `time-dilation`) and does not reject the ride. The same start stores salt commitments the road rebuild does not read. A `protocol: 2` batch may carry deflate streams; the MAC is checked first, and a bad or oversized stream is refused. `stepAt30Hz` is not the live replay rate. Phone minigames are in the server and the cab, and stay off unless `MINIGAMES` is `shadow` or `enforce` ([`minigames.md`](minigames.md) Part 1). `trustScore` is not a device fingerprint and it does not implement the Appendix D point table ([`docs/spec/anticheat.md`](anticheat.md)).

### Live board, watch, chat, donations, replays

**Shipped.** [`docs/spec/replays_streams.md`](replays_streams.md).

`GET /api/live` is heartbeats plus soft online counts and returns no running rides. `GET /api/replays` lists finished 1h rides and omits a finished free, guest, assist, or tutorial ride. A finished free ride, and a running ride, are `404 replay_not_available` on watch and `/road`. A pool ride stays locked until `payoutAt`, except the owner on watch. `GET /api/rides/:id/replays` for another wallet returns the same `404` `not_found` as a missing ride. Watch polls. There is no WebSocket. Public watch samples zero the input column. Donations are replay-only SOL tips, `kind: 'tip'`, from 0.001 to 1 SOL, default 0.01, expiring in 15 minutes, at most 3 open orders, split 95/5 to the driver and the treasury. A tip on your own ride is `400 own_ride`. A non-tip donation effect is `400` with code `donation_effect`. Night, day, and holes are that `400`, not a `404`. `POST watch/:id/honk/time` and `POST watch/:id/honk/weather` throw `NotFoundError` (`404` `not_found`) before any TEN4 debit. The burn under that throw does not run. `GET /api/me/donations` lists sent and received tips. Replay draws the recording. It does not run the sim. Sample columns are append-only. Input bits are frozen.

The replay panel plays and pauses, runs at 0.5×, 1×, 2×, and 4×, scrubs, jumps ±10 seconds, and switches cabin, chase, and hood. It has fullscreen, damage, honk, and minigame marks, volume and mute, a `?t=` share link, and a speed and damage chart. Tip buttons are 0.01, 0.05, and 0.1 SOL. Chat on a finished replay stores `replayT` in the existing applied columns. A line is at most 200 characters. Links and banned words are rejected. The cap is 5 messages per 60 seconds. A moderator can hide a line. A banned wallet gets `403 chat_banned`. Messages older than 90 days are deleted. Tips stay. EN and RU copy is in `frontend/client/site/i18n.js`. The language is `?lang`, then `fc_lang`, then `freightchain.lang`, then the browser, then English.

The watch and donation sentences above are the shipped cells of the live-watch and spectator-effects rows.

### Pre-season social verification (25 October 2026)

Telegram verification requires a Telegram Login Widget proof signed by the configured bot: matching user ID, valid HMAC and at most five minutes old. Membership comes from the configured channel; a restricted account counts only with `is_member=true`. The former four-character prefix code was not wallet-unique.

### Durable ride-token emission (25 October 2026)

When an emitter is configured, a new ride reward records `HonkMint.chainPending` in the same transaction as its ledger reservation/credit. The 60-second release worker claims a two-minute retry lease under the player lock, sends outside the transaction and records a confirmed receipt afterward. Crashes, failed RPC and lost responses remain retryable. Existing ledger-only rewards are not retroactively queued when an emitter is enabled. Immediate verdicts still attempt low-latency delivery; the worker reconciles that receipt.

Local TEN4 `mint_ride` accepts an optional expected amount; the server always supplies the reserved ledger amount. A different era/day cap calculation refuses atomically with `RewardMismatch` (6017), leaving the queue pending rather than silently paying a different amount. Ride receipts now bind the recipient, amount, tier and bands. The adapter validates the program owner, discriminator and complete receipt before acknowledging a retry; an `already in use` error alone is not success. These new local receipt layouts and instruction arguments require the matching fresh TEN4 program, not an in-place assumption about old receipts.

Replay refreshes preserve the last valid recording when JSON decoding fails or the response is missing its recording, ride, batches or events. The next valid poll clears the transient error.

Convoy settlement catches each reward's player-lock/lease acquisition failure as well as delivery failures, so one transient claim failure does not abort the remaining batch.

Successful Telegram/X verification rechecks Convoy milestones against already persisted ride evidence, under both player locks. Completing social tasks last can qualify without another ride; duplicate social/ride callbacks cannot earn twice.

Pool cards and purchase receipts show ticket counts for zero-minimum v6 pools instead of a sold/minimum ratio. Future pools show their opening time; sale close and the last permitted start have separate labels. The lobby omits the minimum-sales progress bar when no minimum exists.

The public landing ticker uses the same replay visibility filter as the replay board before limiting results: training, tutorial/assist, guest, rejected and review-locked pool rides cannot appear, including for a signed-in owner. Newer hidden rides cannot displace older eligible finishes.

Trust points use durable `Player.trustSignals.activity`: +15 for a UTC day with a verified completed ride, at most two distinct days per ISO week and score 100. Partial verified rides do not earn a finish bonus; rejudgements cannot reuse historical credited days. First verified Telegram/X bindings add 5/20 points within a combined 30-point cap. A positive confirmed program-ticket purchase sets trust to 100; duplicate chain events do not re-credit it. Four `trust_finish_*` / `trust_social_cap` settings are available through the signed admin settings API/UI. Existing rejection penalties and reward holds remain. Historical evidence absent before this change is not reconstructed. Discord, ASN and funding-graph acceptance remain open.

The dedicated replay worker retries queue-discovery failures after its configured polling interval, logging `replay-worker.retry`; a transient database outage does not end the daemon. Claimed-job failures retain the existing queue retry policy.

Player wallet and guest sign-ins persist only wallet, time and `ipHash`: a keyed HMAC of canonical IPv4 /24 or IPv6 /48. No raw IP or User-Agent is retained in `player.SignIn`; admin views expose a subnet hash or unavailable. Missing local `IP_HASH_SECRET` disables correlation, production requires a 32-byte hex key. The daily sweep retains sign-ins for 1–90 days (default 90); historical raw fields are discarded by migration. This preserves existing pool shared-network review flags, not proof of a unique person or an automatic TrustScore penalty. Privileged admin/editor audit context remains separate.

SGT trust fast path: authenticated `GET/POST /api/me/trust/sgt` and the Profile control use optional `SGT_RPC_URL`, a separate mainnet read-only provider. The fixed mainnet genesis and canonical Token-2022 metadata/group are required; finalized token and mint evidence verifies positive ownership, including valid frozen accounts. A unique device mint and wallet claim atomically sets trust to 100 once. A transferred previously claimed mint cannot award another wallet, and retries never restore subsequent trust penalties. Claims retain mint/wallet/slot/time across player deletion to prevent replay; no raw provider response or device fingerprint is stored. Unconfigured/provider failures are explicit 503s, absent ownership is 409. No mainnet transaction is signed. Physical-Seeker/live-provider acceptance remains an operator check; local provider fixtures exercise the real adapter, API, database and browser.

Optional IPinfo Core and Helius Wallet API evidence is implemented behind two signed admin opt-ins, both default off. Successful wallet/guest sign-in may retain sanitized ASN/mobile/hosting/anonymous facts with the subnet hash; admin player review may fetch first-funder evidence or a bounded partial transfer page. Mobile networks and known exchange funding are labeled excluded. Missing configuration, provider failure and incomplete history are explicit states. No score/penalty/eligibility change follows these facts. See [provider evidence](../testing/TRUST_PROVIDER_EVIDENCE.md).

Admin operational log buffers retain at most 5,000 entries younger than 30 days, with ClockPort-based filtering and physical removal on reads/writes, startup and a one-minute idle sweep. The shared Redis list preserves duplicate lines and cross-replica append order; a two-minute lease expires it when all app replicas stop. A Redis outage falls back to the age-filtered local buffer. Idle physical cleanup has up to one sweep interval of scheduling delay while running; inaccessible Redis data is removed upon recovery or lease expiry. Host/access log retention is a separate deployment policy. Structured logger fields cannot override the server timestamp.

Alert dispatch and stale-ride timers contain database/cache failures, log redacted failure events and continue on their next scheduled pass. Alert dispatch is single-flight per process; failed outbox reads or retry writes remain pending for a later pass. A failed scheduler dependency cannot create an unhandled timer rejection.

The same timer outage boundary covers program polling/pool sync, pool crank/payout, achievement mint, telemetry/chat retention and the retired daily grant scheduler: cache acquisition and failed lock release cannot terminate the process or prevent the next scheduled pass. Failed acquisition never releases a lock owned by another replica.

Production deployment configuration now routes all service logs and owned nginx access/error logs to a dedicated systemd journal namespace, with Docker caching/host forwarding disabled, hourly expiry, a 29-day target and a 512 MB cap. Scope-isolated Ubuntu acceptance verifies actual expiry and preserved ops readers. This configuration requires an authorized host setup/release; existing live logs were not migrated or deleted. Admin in-memory/Redis retention is documented in its separate implementation change.

Profile `stats.paidRides` counts started non-free shifts, including pool-ticket and granted shifts, independently of legacy transfer-payment records. An unused ticket/order is not a started ride; purchases remain in `ticketsBought` and `spentLamports`. The lobby escrow summary counts only currently selling pools as “on sale”, while its escrow total still includes funds awaiting play, review or payout.

Successful manual ticket reconciliation clears the unfinished-order banner before displaying the paid receipt. The owner CHECK AGAIN flow is accepted in real Chrome with the chain watcher disabled, a real signed local payment, foreign-order refusal and idempotent repeat reconciliation.
