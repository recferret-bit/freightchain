## Решения 59–66 (безопасность админки) — ✅ приняты 17.10.2026
> Владелец принял все рекомендации 59–66 17.10.2026; окончательная формулировка = рекомендация (перенесено из [`OPEN.md`](OPEN.md) раздел B). Канал оповещений решения 64 — Telegram. Нормы — [`admin_security.md`](admin_security.md).

59. ✅ **Роли.** Сейчас один allowlist `ADMIN_WALLETS`: любой админ меняет деньги и видит IP. *Решение:* три роли — `admin` (всё), `moderator` (очередь проверки, реплеи, игроки без ПДн, скрытие и бан в чате по решению 53), `editor` (только storybook). Списки `ADMIN_WALLETS` / `MODERATOR_WALLETS` / `EDITOR_WALLETS`. Публикация сущности редактором — после просмотра вторым редактором или админом (обязательно до mainnet; на devnet — одна подпись редактора + оповещение).
60. ✅ **Деньги и цепь — два шага.** Сейчас override/rejudge платной поездки, hold пула, промо `tickets` и денежные настройки делаются одной подписью одного админа. *Решение:* на devnet-запуске — одна подпись + обязательное оповещение; для платных пулов и mainnet — подтверждение вторым админом в течение 30 мин; `set_config` / `set_pool_rules` в цепи — только через Squads (связано с адресом `team_recipient`).
61. ✅ **Default-deny.** *Решение:* глобальный `PrivilegedSurfaceGuard` по префиксам `/api/admin`, `/api/editor`, `/api/editor/mcp` + мета-тест покрытия guard; guard на классе остаётся.
62. ✅ **Строгий режим старта.** Сейчас проверки только при `NODE_ENV === 'production'`, `DEMO_WALLETS` (в т. ч. `*`) в production не запрещён, `ADMIN_JWT_SECRET` выводится из `JWT_SECRET`. *Решение:* строгий режим при любом `NODE_ENV`, кроме `development`/`test`; старт падает при `DEMO_WALLETS`, `EDITOR_FAKE_LLM=1`, `LIVE_FREE_DONATIONS=on`, `LIVE_EFFECTS≠off`, без отдельных `ADMIN_JWT_SECRET`/`EDITOR_JWT_SECRET`.
63. ✅ **Админ-сессия.** Сейчас 120 мин (максимум 1440), logout не отзывает токен. *Решение:* ≤ 60 мин без продления, `jti` + список отзыва (Redis), отзыв при logout.
64. ✅ **Аудит и оповещения.** *Решение:* запрет `UPDATE`/`DELETE` для роли приложения + триггер; «до/после» в каждой строке; аудит неудачных входов, logout, чтений ПДн и CLI; хранение ≥ 2 лет; оповещения в **Telegram**-чат владельца (вход, любое изменение, 5 неудачных входов за 10 мин, `pending_approval`). Бот-токен и chat id — только через env (`ADMIN_ALERT_TELEGRAM_BOT_TOKEN`, `ADMIN_ALERT_TELEGRAM_CHAT_ID` в `deploy/.env` на сервере), в репозитории секретов нет. Если Telegram недоступен — оповещение не теряется: очередь `admin.AlertOutbox` с повтором до 24 ч, `error`-лог `admin-alert.undelivered` и баннер на странице админки; изменение не блокируется (канал выбран владельцем 17.10.2026).
65. ✅ **Лимиты входа и перебор админов.** *Решение:* бюджет `auth` (30/мин + 5/с) для `/api/admin/auth/*`, `limit_req` на nginx-сайте админки, ≤ 30 изменений/мин на админа; `auth/nonce` всегда `200` (фиктивный nonce для чужих), nonce по ключу (кошелёк + клиент).
66. ✅ **IP allowlist админки.** *Решение:* `ADMIN_IP_ALLOWLIST` (как у редактора) — обязателен для mainnet, на devnet необязателен (хватает basic auth + подписи).
