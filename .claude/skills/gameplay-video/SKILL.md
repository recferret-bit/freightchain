# gameplay-video

Turns a text description into `media/out/video/<name>/<name>.mp4` + `.gif` + `contact.jpg` (+ the sound in `media/out/audio/<name>/`), plus compressed copies `<name>.min.mp4` + `<name>.min.gif` that look like the originals at a fraction of the size, and `<name>.tiny.gif` (whole clip ≤ 500 kB). The footage is the real game (`client/play.html`, headless Chrome, scripted driver), not a mock-up. Harness: `media/` (`make.mjs` orchestrates; `video/` = capture + encode, `audio/` = the sound, `specs/intro.json` = the worked example).

## Modes – pick by what the user asks (all from `media/`, one spec; `npm run media -- media/specs/<name>.json <flag>` from the root)
| user wants | run | result |
|---|---|---|
| video + sound (default) | `node make.mjs specs/<name>.json` | silent mp4 + gif + `timeline.json`, then `audio/*.wav`, then the sound muxed onto the mp4, then the `.min` / `.tiny` copies |
| video only | `--video-only` | silent mp4 + gif + contact sheet + `timeline.json`; no sound even if the spec has `audio` |
| sound only | `--audio-only` | `out/audio/<name>/{mix,music,sfx,engine}.wav` + `cues.json`; no Chrome, no video needed (synced to `timeline.json` when it exists, else the engine is steady and there are no shift / crash cues) |
| (re)do the sound of an existing clip | `--remux` | `--audio-only` + replaces the audio of `out/video/<name>/<name>.mp4` (picture stream copied, never re-encoded; old audio replaced) + refreshes `.min.mp4` |
| **sound for a file the user picks** | `--add-audio path/to/file.mp4 [--out new.mp4] [--timeline t.json]` | `<file>.sound.mp4` (or `--out`); the original is never overwritten. The spec may hold ONLY an `audio` block (`{"name":"x","audio":{"ignition":{"dur":0.7},"music":{"id":"road-rush"}}}`) – the clip is then as long as the file and there are no scene cues; a spec WITH scenes must add up to the file's length (±0.1 s) or it refuses |
| only the compressed copies | `--compress` | `.min.mp4` (keeps audio) / `.min.gif` / `.tiny.gif` |
`--preview` (half size, 12 fps, name `<name>-preview`) combines with every mode; `--only a-b` is video only (`-partial`). One mode per run. Sync note: shift / crash cues come from `timeline.json`, which only a capture writes – for a foreign mp4 give `--timeline` or accept an unsynced soundtrack (music + ignition + effects from the spec's events).

## Workflow
0. Needs Node ≥ 22, Chrome, and `npm --prefix media install` once (ffmpeg-static downloads its binary on install).
1. **Text → spec.** Read `media/specs/intro.json` and write `media/specs/<name>.json` from the user's description, using only the vocabulary below. Pick scenes that show a *mechanic* (crash, gears, lights, frost, dust), one caption per scene, the end card last.
2. **Preview** (≈1 min): `cd media && npm install` (once) then `node make.mjs specs/<name>.json --preview`. Open `out/video/<name>-preview/contact.jpg` with Read and check text, cuts and that the scene shows what the caption claims (a crash must actually crash).
3. **Final render** (≈2 min): `node make.mjs specs/<name>.json` (`--keep` keeps the JPEG frames, `--only 3.0-5.4` renders just a time range into `out/video/<name>-partial/` for testing one scene – it never touches the real clip; `VERBOSE=1` logs every frame's rpm/gear/clutch).
4. **Sound** (if the spec has `audio`): the render prints `audio … N cues` and `mux`; `--remux` rebuilds only the sound from the saved `timeline.json` and puts it on the existing mp4 (seconds) – use it to tune levels / cues without a new capture. Look at the waveform (`node audio/cli.mjs wave out/audio/<name>/mix.wav`, then Read the PNG) against `contact.jpg`; you can't hear it, so tell the user what to listen for (level balance, crash punch, ignition length).
5. **Report** the printed numbers (mp4 seconds + MB, gif MB / width / fps / whether it was trimmed, the two `.min` sizes, the `.tiny.gif` kB + rung), show `contact.jpg`, and say what a human must eyeball: transition punch, caption timing/legibility over busy footage, crash readability, how the gif looks at 640 px. Frames are not judged for "feel" by the script.

Everything is deterministic (virtual clock + seeded `Math.random`, seeded synth): the same spec on the same machine + game code gives the same files, so a fix to one scene does not reshuffle the others. It is **not** stable across game changes: the committed intro was rendered before later game / harness edits and a fresh render differs from t ≈ 3.5 s on (other traffic, the crash ~0.5 s later) – when re-rendering a committed clip, compare `contact.jpg` with the committed one and tell the user.

**Compressed copies** (`media/video/encode.mjs` `compress`, `MIN`): every full render also writes `<name>.min.mp4` (H.264 crf 24 from the finished mp4 ≈ 37 % of its size, SSIM ≈ .985) and `<name>.min.gif` (same width / fps / length as the original gif, 128 colours, Bayer dither ≈ 80 % of its size – plain ffmpeg can't do much better without visible loss; no-dither bands the sky, gifsicle `--lossy` was rejected for its npm dependency chain). The originals are never touched. They're made from the finished `.mp4` + `.gif`, not the frames, so `node make.mjs specs/<name>.json --compress` (no capture, seconds) remakes them for an already committed clip, with the same bytes a full render would give. **Tiny gif** (`TINY`): the whole clip in ≤ 500 kB (decimal) for embeds / chats – a ladder from 320 px @ 6 fps down to 160 px @ 4 fps, 32–48 flat colours (no dither: noise costs bytes); the intro lands on 240 px @ 5 fps, 48 colours ≈ 476 kB. Headlines and the end card stay readable, the ticker / gauges don't, and motion is choppy – it's a teaser, not a master. If no rung fits it fails instead of trimming. Not made for `--preview` / `--only`. Use the `.min` files where size matters (landing, README, socials) and the originals as masters.

**Finished clips are committed** (`media/out/video/<name>/{<name>.mp4, <name>.gif, <name>.min.mp4, <name>.min.gif, <name>.tiny.gif, contact.jpg, timeline.json}` and, for a clip with sound, `media/out/audio/<name>/{mix,music,sfx,engine}.wav, cues.json`); previews / partials / frames are gitignored. When the user approves a new or changed clip, commit its files with the spec.

## Limits the harness enforces
- `maxSeconds` (default 15): `loadSpec` rejects a spec whose scene durations add up to more, and the mp4 is re-measured after encoding (`-t` hard stop). A longer clip sets it explicitly (`specs/colosseum.json`: 59 s, the Colosseum progress collage); it gets no `.tiny.gif` (over `TINY.maxSeconds` 20 s) and its music repeats the score (see `game-audio`).
- GIF: the 20 MB limit is on the **.gif file on disk** (`gif.maxMB`). `encodeGif` walks a ladder (640 px/15 fps → 12 fps → smaller/slower) and only then trims the clip; the result line says `TRIMMED to fit`. If the user meant something else by "20 MB uncompressed", ask.
- **Sound** is opt-in: a spec with an `audio` block gets a soundtrack (the game's own synth is muted in the capture); without it the clip is silent as before (`hero` – the landing's muted loop – and `intro-square` stay silent). The music and effects are synthesised offline by `media/audio/` (original, nothing licensed, nothing sampled) – see the `game-audio` skill for the `audio` vocabulary, the sound store and how to add sounds. The mux re-checks the 15 s limit; `.gif` has no sound by nature.

## Spec vocabulary (`media/video/spec.mjs` validates it)
Top level: `name`, `fps` (24), `width`/`height` (1280×720), `maxSeconds`, `gif {maxMB,width,fps}`, `ticker` (scrolling LCD strip text), `look`, `crop`, `scenes[]`.
- **`look`**: `classic` (default: ticker, brand + route chip, Solana badge, numbered typewriter captions with a sub line, end card with step chips + footer) or `big` – **no small text**: all of that is hidden, each caption is ONE huge word block (`head` only, `\n` = line break, auto-fitted to the frame, slams in), the end card is just the truck mark + `title` lines + the CTA. For icons / thumbnails. `specs/intro-square.json` is the worked example.
- **`crop`**: `"square"` = capture at the usual 16:9 (the cockpit keeps its normal layout – a native square viewport shrinks the windscreen and wastes the bottom on the steering wheel) and encode only the centre `height×height` square; the overlay lays itself out inside that square. Mirrors and the side switches fall outside the crop.

Scene: `id`, `dur` (s), `shots[]` + `bg` (collage, below), `route` (`route66|stuart|siberia|brenner|panamerican`), `time` (`day|night|dusk|dawn`), `speed` (m/s, or `[from,to]` ramp), `gear` (omit = chosen from the speed; the driver upshifts by itself at ~2350 rpm with real clutch dips), `lights` (headlights; default on at night), `cab`, `cold` (engine starts at ambient, for frost), `preroll` (s of un-captured game time so frost/dust has built up), `traffic`, `damage` (let hits hurt – needed for a crash), `seed` (re-roll just this scene's random stream: every scene draws from its own, so changing the world generator or an earlier scene never reshuffles it – but if a no-damage scene happens to end in a crash, change its `seed`; the timeline's `crash.why` says what hit), `sway`, `push` (slow zoom-in, 0.08 = 8 %), `grade` (CSS filter string), `transition` (INTO this scene: `"flash"` or `{type,dur}`), `events[]`, `captions[]`, `card`.
- **transition types:** `cut flash flash-red glitch whip zoom dip` (the cut is hidden under the peak; dur ≈ 0.3–0.4 s).
- **events** `{t, do, …}` (t = scene-local seconds): `gear {value}`, `lights {on}`, `cab {on}`, `wipers {mode 0|1|2}`, `washer {on}`, `heater`, `night {on}`, `phase {value}`, `spawn {type,preset,zone,dist,lat}` (see docs/agents/gameplay.md "Traffic": a `truck`/`slow` spawned `ahead` at ~20 m while driving 25 m/s is a guaranteed direct hit = the ride-over stamp and red flash appear by themselves), `steer {value}`.
- **shots** (a collage over the road – pair with `grade` to blur / darken it and `bg: "sol"` for the Solana glow + grid): `{src, at, dur, x, y, w, h, fx, rot, tilt, scroll:[a,b], zoom:[a,b], origin, frame, label, z}` – `src` = a screenshot in `media/assets/` (served at `/__assets/`), or `stat: ["14", "INSTRUCTIONS"]` for a counting stat card; `x y w` in 1280×720 frame pixels (`h` = a window onto a taller image, panned by `scroll` 0–1); `fx` how it lands: `pop slide-l slide-r slide-u slide-d drop flip zoom` (always with an RGB-split flash); `frame` `sol` (default gradient border) or `amber`; `label` = an LCD chip on the frame; no `dur` = stays to the scene's end. Keep tiles off the caption box (bottom-left, y > ~520, x < ~800). A scene with shots hides the route chip, and its engine bed is muted (`engine: true` keeps it). Cues: `tr-whip` per sliding tile, `click` per pop / stat. The screenshots come from the e2e suites' `SHOTS` dirs + static pages (docs/, the whitepaper); curate them as JPEGs into `media/assets/<clip>/` and commit them with the spec.
- **captions** `{n:"01", at, dur, head, sub}`: typewriter headline + sub line + progress bar, bottom-left (`look: big`: only `{at, dur, head}`, centred over the windscreen).
- **card** (end card, layered over the blurred road): `{title:[line1, accentLine], steps:[3 chips], cta, foot}`.

## House style and copy rules
Look = the landing (`landing/src/style.css` tokens: dash black, amber `#ffcf5a`, needle orange, cream, LCD green ticker, mono type) plus the Solana gradient badge. Keep the arc: *take a paid ride → obstacles → long shift → compete on every route → win prizes → CTA*. Copy must stay consistent with what the product honestly is (landing + AGENTS.md): **Solana devnet build**, finishers share **one weekly SOL pool**, shifts are **30 min** in production; no payout amounts, no "guaranteed", no mainnet claims, no draw/jackpot language (prizes are a top-N split, settlement/payout is not built yet). If the user asks for stronger claims, flag the gap instead of writing it in.

## Extending
- New effect/transition: `draw()` in `media/video/page.js` (pure function of the video time `T`; never use CSS animations or timers – the clock is virtual). New game action: `fire()` there + add the name to `EVENTS` in `media/video/spec.mjs`.
- The page code depends on `window.__game` (client/js/main.js) and the physics rules in `client/js/sim/physics.js` (`input.clutch` is boolean, `shiftT` holds the clutch ≥ .9) – re-run the preview after touching those.
- **Rendering:** capture uses the real GPU (`--use-angle=metal`, macOS) by default. Software GL (SwiftShader) z-fights the road ribbon against the ground, so the asphalt blinks while moving (and night headlight pools flicker); `GPU=0` forces software rendering – don't use it for final renders. If a clip shows flashing road, check this first.
- **Render committed clips from committed game code**: the capture serves the working tree's `client/`, so uncommitted game changes (another session's WIP) end up in the footage. If `git status client` is dirty, render in a clean `git worktree add --detach <dir> HEAD` with the `media/` changes copied in and `media/node_modules` symlinked, then copy `out/video/<name>/` back.
- Output goes to `media/out/video/<name>/` and `media/out/audio/<name>/` (previews / partials gitignored). Chrome: `CHROME=/path`, debug port `PORT` (default 9555; `client/tools/cdp.mjs`).
